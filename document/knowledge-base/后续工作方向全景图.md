### 1.1 三大模块现状盘点

目前只做了全景图中的一部分。下面按 ①②③ 三块标清楚"已做"和"规划中/后续做"，避免把长期方向误读成当前已实现。

|---|---|---|---|
| ① 智能体 Agent | 双 Agent、需求类型识别、人工接管/交还 AI、坐席回复建议、渐进式留资、confirm_dialog、页面上下文、基础对话埋点 | 多智能体协作、个性化、多模态、多渠道、语义缓存、模型分级路由、并行工具 | 已做的是智能客服主链路与坐席协同，复杂智能化能力仍属后续 |
| ② 知识库 KB/RAG | N5 知识库配置原型、知识资产目录、知识板块、元数据规范、门户网站范围、健康度权重/高级配置、同步状态多选、问答测试、对话质量运营、知识健康体检、未命中主题查看对话与补录闭环 | 完整溯源、冲突消歧、知识去重、Rerank 深调、知识图谱、多模态知识、行业知识包 | 第二期重点是客户后台知识运营闭环，不是一次性做完全部 RAG 进阶能力 |

### 1.3 知识库升级闭环（第二期先落地）

第二期不是做完整全景图，而是先把全景图里最关键的知识运营闭环落地：

```
门户网站范围选择
        ↓
知识录入 / 同步 / 分组
        ↓
知识板块处理策略（切片、清洗、质量评估、检索策略）
        ↓
元数据规范与健康度规则
        ↓
问答测试验证召回和回答效果
        ↓
前台智能客服产生真实对话
        ↓
对话质量运营发现召回、回复、准确率、满意度和损耗问题
        ↓
知识健康体检聚合过期文档、待补 FAQ、未命中主题 Top
        ↓
查看原始对话，确认用户真实问题
        ↓
跳转知识资产目录补录 / 忽略 / 后续复评
```

这条闭环对应的是全景图中的 ② 知识库和 ③ 评估与监测。① 智能体提供真实对话数据来源；已有底座提供任务、权限和隔离保障。

### 1.4 全景图落地原则

| 原则 | 说明 |
|---|---|
| 先闭环，后智能化 | 先让运营能看见问题、定位问题、补录问题，再逐步做自动推荐、自动补全、自动评估 |
| 先单客户，后跨客户 | 客户后台先只看本客户；平台后台再看跨客户质量诊断、行业共性问题和客户成功队列 |
| 先人工可控，后自动优化 | 高风险动作如知识发布、冲突裁决、忽略主题，初期保留人工确认 |
| 先可解释指标，后复杂算法 | 指标先用业务可理解的召回、回复、准确率、满意度、未命中主题，后续再补 RAGAS、红队、成本模型 |
| 页面可以变，链路不能断 | 具体页面命名和布局可以随原型调整，但"知识输入 → 检索回答 → 质量监测 → 缺口补录 → 复评"必须保留 |

## 二、① 智能体 Agent

## 三、② 知识库 KB / RAG

目标：**答案有据、来源可查、知识常新。**

### 3.1 RAG 回答准确性

| 方向 | 当前状态 | 要做什么 | 衡量指标 |
|---|---|---|---|
| 解析质量 | 已做原型级门禁，后续增强 | 已有切片预览、解析问题、质量门禁；后续可评估 DeepDoc 等高保真解析方案 | 解析准确率、表格完整率 |
| 分块策略 | 已做板块级配置原型，后续增强 | 已有板块切片解析配置；后续按内容形态优化父子分块、语义分块 | 检索命中率提升 |
| 混合检索调优 | 已做策略配置原型，后续深调 | 已有向量权重、阈值、TopK、Rerank 等配置心智；后续做真实检索回归调优 | Hit Rate@k、MRR |
| 防幻觉 | 规划中 | 检索不足时拒答/说"不确定"，不编造 | 幻觉率、拒答合理率 |
| ★ 知识冲突检测与消歧 | 后续做 | 同问不同答、新旧版本冲突的发现与裁决 | 冲突检出率、消歧准确率 |

| ★ 知识去重 | 规划中 | 重复/洗稿内容合并，避免检索冗余 | 去重率 |

### 3.2 溯源与出处展示（你提的网页出处链接 → 扩展成完整溯源体系）

不只是网页——**每类知识都应可溯源**，落地为统一的"出处卡片"：

| 知识来源 | 当前状态 | 溯源展示方式 |
|---|---|---|
| ⑤ 网页 | 规划中 | 展示**原文 URL 出处链接** + 抓取时间 |
| ① 文档 | 规划中 | 定位到**文件名 + 页码 + 段落**，点击跳转预览 |
| ④ 内容资产 | 规划中 | 链接到**原文章/详情页** + 发布时间 |
| ③ 结构化数据 | 后续做 | 标注**字段来源与查询时间**（实时直查，注明数据时点） |
| ② FAQ | 规划中 | 标注命中的**标准问 + 知识库归属** |
| ★ 可信度分级 | 后续做 | 按来源权威度/时效给引用打可信标签（官方/外部/生成） |

> 后续实现建议：检索结果携带来源元数据，前端渲染为可点击的引用卡片。具体字段和展示方式以研发阶段的数据结构为准。

## 四、③ 评估与监测 Eval

目标：**一切可量化、可定位、可优化。** 当前先落业务可理解的指标闭环；OpenTelemetry、Langfuse 自托管、RAGAS 属于后续评估技术选型建议，不表示当前已建成。

### 4.1 智能体评估

| 维度 | 当前状态 | 评什么 | 工具/方法 |
|---|---|---|---|
| 任务完成 | 已做基础业务指标 | 解决率、转人工率、一次性解决率 | 业务埋点 + 标注 |
| 意图与路由 | 已做需求类型识别，后续回归评估 | 意图识别准确率、路由正确率 | 黄金意图集回归 |
| 工具调用 | 规划中 | 调用成功率、参数提取准确率、超时率 | 后续可接 trace 统计 |
| 多轮对话 | 规划中 | 上下文连贯性、指代消解正确率 | LLM-as-Judge + 人工 |
| ★ 安全合规 | 后续做 | 越权/注入拦截率、违规输出率 | 红队测试集 |
| ★ A/B 测试 | 后续做 | 新 Prompt/模型/参数的效果对比 | 分流实验框架 |

### 4.2 知识库质量评估（三层，详见《知识库体系架构方案》§6）

| 层 | 当前状态 | 评什么 | 指标/工具 |
|---|---|---|---|
| 解析/分块 | 已做原型级门禁 | 入库前质量门禁 | chunk 抽检 + 规则（空块率/表格完整率） |
| 检索 | 已有召回率，后续回归评估 | 能不能召回对的内容 | Hit Rate@k / Recall@k / MRR |
| 端到端答案 | 已有 RAG 准确率代理指标，后续接评测工具 | 准不准、有没有幻觉、引用对不对 | 后续可选 RAGAS 等评估工具 |
| 资产健康度 | 已做 | 综合质量×时效×复用×反馈 | 健康度评分卡，驱动保持/整改/下线 |

### 4.3 埋点监测使用效果

| 维度 | 当前状态 | 监测什么 | 说明 |
|---|---|---|---|
| 用户行为 | 已做基础对话埋点 | 会话量、对话时长、活跃用户、留存 | 评估"用得多不多" |
| 满意度 | 已做原型指标 | 赞/踩比、CSAT、NPS、纠错率 | 当前先看满意度/点踩，NPS 和纠错后续扩展 |
| 业务效果 | 已做知识质量指标，后续接转化 | 客服解决率、转人工率、内容产出效率/转化率 | 评估"有没有业务价值" |
| 性能 | 已有首字响应等基础指标，后续完善 | 首字延迟、P95 时延、QPS、可用性 | 评估"快不快、稳不稳" |
| ★ 成本 | 后续做 | Token 消耗、GPU 算力、单次问答成本 | 评估"贵不贵、可持续性" |
| 监测平台 | 后续技术选型 | 全链路 trace、看板、告警 | 可评估 OTel + Langfuse 等方案 |

### 4.4 ★ 持续优化闭环

评估不是终点，而是飞轮的起点：

```
[监测埋点] → [发现问题(低命中/高幻觉/慢/负反馈)] → [定位(对话/检索/评估记录下钻)]
     ▲                                                          │
     │                                                          ▼
[效果复评] ◄── [优化(调分块/参数/Prompt/补知识)] ◄────────────────┘
```
