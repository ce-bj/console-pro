# 知识库升级二期

## 概览：网站知识画像

### 定位与展示

放在概览关键指标下方，保留原有待办、快捷入口和知识分布。将知识库输入转化为用户可检查的企业信息成果，不新增知识板块，也不直接回写网站或作为未经确认的独立知识来源。

生成内容来自本门户适用知识的融合总结，既支持非结构化切片，也支持后台数据源、产品规格、表格文件等已入库的结构化记录。不能用“不是后台字段”解释画像：后台数据正是有效知识来源之一。边界是是否按现有接入规则进入知识库并生效，而不是原始数据来自前台还是后台。不得用简单拼接代替去重、归纳与一致性核对。

### 与一期录入、二期结构化数据及接入更新的闭环

接入方式、知识板块、业务分类分别承担不同职责：接入方式确定原始内容维护和更新路径；板块确定解析与检索方式；知识库类型及一二级分类确定业务归属与调用范围。画像不新增另一套分类，也不把所有内容转换成文档或再次复制入库。

| 现有入口 / 接入方式 | 归入板块 | 画像依据 | 补充纠正与后续动作 |
|---|---|---|---|
| 上传文件 / 对象存储 | 文档知识 | 文档及有效切片 | 更新原文档，或编辑切片；解析学习完成后重生成，不展示立即同步 |
| 上传问答模板、录入问答 | 问答知识 | 标准问题、答案、相似问法 | 编辑问答或更新模板文件；学习成功后重生成 |
| 上传 Excel、CSV、JSON、JSONL | 结构化数据 | 数据集中的有效记录及授权字段 | 更新源文件并校验结构，重新学习；不引导用户修改后台产品字段 |
| 选择前台页面 | 内容资产 | 已入库页面正文及有效片段 | 修改网站内容并发布；正文修改实时同步，栏目新增/删除由接入与更新管理 |
| 选择后台页面，选择内容资产 | 内容资产 | 应用/数据源内容的有效片段 | 原应用维护内容，沿用栏目更新、使用开关与学习规则 |
| 选择后台页面，选择结构化数据 | 结构化数据 | 应用→数据源→记录→字段；需要时关联子表 | 原应用维护字段和记录；知识库只管理接入范围、字段用途和记录可用性，不新建产品属性模板 |
| 产品规格独立入口 | 结构化数据 | 已开启规格的产品及其 SKU 记录 | 原产品管理开启并维护规格，单独接入；不能因为接入产品数据源就视为接入全部规格 |
| 学习外部网址 | 网络知识或文档知识 | 已抓取学习的页面或文档 | 检查网址和抓取更新；无外站编辑权限时可上传补充文件 |
| 导入平台知识 | 行业知识 | 企业已导入且有效的行业资料 | 检查并导入更新，不自动覆盖企业版本；仅作行业参考，不推导企业拥有某资质、产品或服务能力 |

“产品”应用可分别接入内容资产与结构化数据，两者并存但证据通过来源记录标识去重。产品介绍用于归纳用途与特点，结构化记录用于准确名称、型号、数值和单位；不能混合不同 SKU 的重量、价格或库存，也不能把子表行误当作独立产品计数。

结构化字段沿用二期六种能力：搜索/筛选用于定位记录，聚合/排序仅在授权配置允许时执行，展示控制返回给用户的字段，AI 控制是否允许字段内容进入模型总结。不能因为页面能看到某字段就默认允许发送给模型；需要聚合时由结构化查询计算，模型不凭片段推算全量数量。多条记录引用需保留产品/记录标识与单位。停用行、不可用切片、失效知识与越权字段不作为新的生成依据。

依据面板显示真实知识资产名称、板块、接入方式、切片或记录位置、原始来源、最近学习时间和可用状态。知识名称进入资产详情，维护入口按来源方式进入现有接入与更新并定位知识名称。依据是生成时快照；来源发生改变后标识需更新，不能把新原文冒充旧摘要的历史依据。

闭环顺序为：画像发现缺失/错误 → 优先定位已有知识维护 → 没有知识时复用新增知识的六类入口及板块限制 → 草稿启用、校验、学习 → 更新知识可用版本 → 标识相关画像待重新生成 → 重新生成 → 更新画像及对应知识依据。重新生成不等于同步来源，也不会自动发布草稿或开启已关闭的栏目。多个新任务中部分失败时保留上次结果并提示未完成范围，不宣称全量刷新成功。

健康度与画像完整度分开：低健康度指向现有知识体检及整改，不把健康分当事实可信度；完整度只是字段是否填写，不能说明内容准确。知识被停用、删除或过期时，对依赖字段标记依据不可用；无其他依据则该字段清空或待确认。权限收回时立即隐藏受限内容，而不是等下一次生成。

以当前门户为边界；门户选择沿用已授权站点。画像、补充任务、来源证据和生成任务均按企业及门户隔离。不能把中文站摘要直接复用到英文站，不能把行业通用资料当成企业事实。只使用本门户有权限访问、已启用且完成学习的适用知识。

头部显示门户、域名、已整理字段数/全部字段数、待补充数、待学习/待生成数量、最近成功整理时间。左侧分组显示各组完整度；右侧为字段名、内容、来源与操作，支持“只看待补充”。统计按字段计数，多个产品仍属于一个主营产品字段。

| 分组 | 字段 | 缺失时建议维护位置 |
|---|---|---|
| 公司信息 | 公司名称、公司简介、所属行业、成立时间 | 网站设置/公司信息、网站内容/关于我们 |
| 品牌信息 | 品牌名称、品牌定位、品牌口号 | 网站内容/品牌介绍 |
| 主营业务 | 主营产品、服务内容、应用场景 | 产品管理/产品、网站内容/服务介绍 |
| 产品与服务优势 | 核心优势、定制能力、服务地区 | 网站内容/产品优势、服务介绍 |
| 荣誉与资质 | 企业资质、产品认证、专利与荣誉 | 网站内容/荣誉资质 |
| 企业实力 | 生产能力、研发与质控 | 网站内容/工厂介绍、研发与质量 |
| 案例与客户 | 代表案例、合作客户 | 网站内容/客户案例 |
| 联系与咨询 | 联系电话、咨询邮箱、公司地址 | 网站设置/联系方式 |

产品、案例、资质等可包含多个项目，逐项保存证据，展示时分项排列。证据需包含知识资产ID、记录/切片ID、原文位置、来源更新时间与门户。资质有效期、产品数值、客户名称等只能依据来源，不补猜测值。多个来源矛盾时保留原值并标记待确认，由用户核对，不自行选择。

### 统一补充与重新生成（以本节替代原画像直接编辑设计）

画像是知识库的结果视图，不独立维护第二份企业资料。删除画像“编辑”、人工覆盖和建议对比功能；每个字段只保留“补充知识”“重新生成”，已有依据可进入原知识维护。不能只改画像而不写入知识库。

画像区分“去后台补充”和“新增资料”。前者进入当前门户的原网站栏目或原应用数据源编辑页，不能跳到知识详情假冒后台编辑；后者携带上下文直接进入既有新增知识页面，不再弹出新入口面板。参数包括 from=website-profile、profileSite、profileField、profileLabel、profileGroup、returnTo。它们是导航和任务归属信息，不新增客户自定义元数据字段；不能将画像分组擅自当成知识库一二级分类。当前门户预设为新增知识适用范围，仍须校验来源站点及用户权限。

新增页仅显示“门户名称 / 待补充字段”和“返回画像”，不展示流程解释、手工填写建议或维护路径段落。继续沿用“选择动作→选择板块→添加内容→元数据→保存”的流程。用户自行选择文件、问答、前台、后台、网址或平台知识；不根据画像字段强制推断来源。不改变行业/知识库类型必填、来源和板块兼容性、已接入状态、文件格式等现有限制。

原后台补充流程：点击去后台补充（编辑入口须携带门户和栏目/数据源/记录标识）→在原后台保存并发布→返回知识库；已有接入通过实时事件更新，必要时从“更新与学习”手动获取最新内容及重新学习；未接入则带已完成的来源选择进入新增流程，不能要求用户重复上传后台已有资料。只有成功入库学习后才更新画像。后台填写、来源同步、知识学习和画像生成分别展示实际状态，不能将“已返回”当作任务成功。

原型后台编辑入口由 mockSourceEditorLinksData 按门户及来源标识映射。当前仓库没有真实网站内容或应用编辑路由，因此入口禁用，仅提供位置提示，不伪造新后台页。研发联调必须用已授权的编辑地址替换映射，并处理缺失模块、无编辑权限、未发布和保存失败。这个跳转步骤尚未在当前原型接通。

手工文字补充选择已有“录入问答”，可预填“请介绍{字段名称}”作为问题提示，答案由用户填写且仍必填。资料保存为问答知识，不能将生成的旧画像自动作为新的事实证据。修正已有答案应进入原问答维护，不重复创建；已有栏目也不得通过新增再次接入。

| 路径 | 原操作与中间状态 | 回到画像的完成条件 |
|---|---|---|
| 手工补充 | 新增页录入问答→保存草稿→目录启用→学习中 | 学习成功且知识有效后重新生成，引用新问答 |
| 新上传文件 | 按原板块上传和校验→保存草稿→启用→解析学习 | 成功后引用文档切片/问答/结构化记录；失败则留原画像 |
| 替换已有文件 | 原知识的更新文件→保存并学习 | 不另加立即同步；任务成功后重新生成 |
| 前后台栏目尚未接入 | 先在原网站/应用维护→新增页选择栏目或数据源→建立接入关系 | 完成启用和首次学习，不以“已选栏目”视为完成学习 |
| 已接入前后台内容已修改 | 原后台发布→实时更新；必要时在接入与更新立即同步、在目录重新学习 | 等待更新和学习成功；点击检测变化并不代表已学习 |
| 已接入栏目新增/删除 | 接入与更新检查变化→按自动策略或立即同步处理 | 新增知识学习完成、删除依赖失效后重新生成 |
| 外部网址或平台导入 | 沿用原网址抓取/平台导入规则 | 抓取或导入知识启用学习成功后再用，不推导无证据的企业事实 |

保存后仍进入知识资产目录的草稿筛选，保留返回画像上下文；不直接跳回并显示成功。目录、详情、接入与更新提供“返回知识画像”，恢复门户及分组。原型记录本次补充生成的知识ID，画像显示其草稿/学习中/启用状态及查看入口。生成只处理有效知识，不能自动发布草稿、解除停用或将失败任务标成成功。

重新生成失败保留上次结果。存在冲突时要求先核对并纠正源知识，不能通过“直接编辑画像”掩盖冲突。生产环境按学习成功事件标记受影响字段待生成，避免用户不断点击无效刷新。

### 补充来源与返回刷新

缺失与已有字段统一提供“补充知识”，携带上下文进入原新增页。提示后台维护位置只作方向指引，不替代原业务编辑页面。原资料已经接入时通过知识依据进入详情或更新页，避免重复导入；所有新资料都必须先成为知识资产，再参与画像生成。

| 实际情况 | 操作与后续结果 |
|---|---|
| 网站原文缺失 | 跳转对应栏目填写并发布；返回后检查来源是否已接入 |
| 网站有内容但未接入知识库 | 引导至新增知识选择该栏目，不直接把未学习内容用于画像 |
| 已接入，待更新 | 引导接入与更新处理，沿用自动更新/手动同步规则 |
| 学习中 | 显示读取进度，学习成功后重新整理相关字段 |
| 学习失败 | 保留当前画像，展示失败原因及重新学习入口 |
| 学习成功 | 更新自动字段；根据生效知识重新生成受影响字段 |

例如运营在“荣誉与资质→企业资质”点击补充知识，在当前门户荣誉资质栏目新增证书，或直接上传证书文件到知识库。完成知识学习后，画像结合已有企业介绍、资质文件等内容整理资质名称与有效期；证书不含有效期则不得推测。如果与其他来源冲突，先核对原知识，再重新生成。

### 原型与交付边界

原型覆盖三个门户、八个分组、知识依据、带参数进入原新增页、手工问答预填、保存草稿与返回入口、补充知识状态和重新生成。不存在画像直接编辑的独立保存入口。

当前工程没有网站内容编辑模块及真实学习服务。前后台维护路径仅作提示；真实上传解析、同步、学习成功回调、冲突处理和多源融合由研发对接。手工问答示例可在知识变为启用且有效后，使用其已存答案演示结果更新；这不是接入了大模型，也不表示上传文件已实际完成解析。页面会话内保留上下文，刷新恢复示例。

验收重点：补充一定形成知识资产；保存草稿不改变画像；失败/学习中不提前刷新；原栏目不重复接入；已有知识更新保留身份与来源；返回恢复门户和字段分组；生成不会绕过可用状态及权限。


## 结构化数据：平台默认规则、通用接入与记录运营

### 1. 定位与本次范围

本模块参考《通用结构化数据入库与检索平台设计方案》，将“字段类型 + 字段能力 + 平台默认值 + 用户覆盖”落在现有知识库中。解决不同客户的应用、数据源、字段结构不同，却都需要按真实业务数据回答问题的问题。不把某一家客户的产品属性模板当作全平台模板，也不把结构化数据统一转换成无来源的文本切片。

本次调整属于二期；一期文档与验收基线不变。以下是产品与研发规则，页面只保留配置项、直接影响及必要提示，不展示“当前版本 v1”、索引实现原理等说明。

| 设计决策 | 为什么这样做 | 带来的价值 |
|---|---|---|
| 平台按字段类型提供六项默认能力 | 不同应用可能使用相同类型，平台不应逐客户配置字段 | 平台统一保障检索能力，运营无需从零配置 |
| 应用、数据源、字段在原业务后台维护 | 防止两套字段模型不一致 | 新增知识只选择范围，后续按源数据更新 |
| 产品规格单列为特殊数据入口 | 产品规格不是应用中的独立数据源，且需要按产品开启 | 数量和选择范围准确，也能扩展其他特殊业务来源 |
| 每行是一条可管理的知识记录 | 停用一行不应停用整个文件或应用 | 可按行修正知识信息、启停和批量运营 |
| 原业务字段与知识增强信息分离 | 知识编辑不能改写价格、库存、产品属性 | 业务事实仍来自业务系统，关键词、问题、标签可独立维护 |

### 2. 页面与角色分工

| 位置 | 权限 | 负责内容 |
|---|---|---|
| 知识板块 → 结构化数据 → 平台级设置 | 平台管理员；后台用户不可查看知识板块 | 字段类型默认用途、推荐规则、召回、返回规模、结构异常处理 |
| 同页 → 入库前清洗与质量评估策略 | 平台管理员 | 脱敏、去重、质量拦截阈值，影响所有客户新处理的结构化记录 |
| 新增知识 → 上传文件 / 选择后台页面 | 有知识新增权限的后台用户 | 上传文件、选择应用下数据源或特殊数据、填写原有元数据 |
| 知识资产目录 → 结构化数据 | 有知识查看权限的后台用户 | 数据集级列表、状态、分类及来源 |
| 知识详情 → 结构化数据记录 | 查看权限可读；知识编辑权限可启停、编辑知识信息和批量处理 | 表格化记录、按行知识信息与状态 |
| 记录区域右上角 → 字段设置 | 当前知识的编辑权限 | 覆盖当前数据集的六项字段用途，不编辑字段名称、类型和业务关系 |
| 客户网站原应用设置 / 产品管理 | 原系统对应权限 | 维护应用、数据源、字段、产品属性模板与产品规格开关 |

原型沿用全权限展示。研发必须在服务端校验客户、网站、知识权限及来源权限；隐藏菜单不代替鉴权。字段用途配置不能扩大原应用的数据授权。

### 3. 平台级设置

#### 3.1 六项字段用途

| 页面名称 | 定义 | 例子 / 边界 |
|---|---|---|
| 搜索 | 字段内容参与关键词检索 | 产品名称、文章标题、详情正文；不是筛选开关 |
| 筛选 | 允许字段作为等值、范围或集合查询条件 | 颜色等于红、重量小于等于 2；操作符受字段类型约束 |
| 聚合 | 按字段值或区间统计数量、生成筛选项 | 按颜色统计记录数；不是任意求和接口 |
| 排序 | 允许按该字段值排序 | 按重量、发布时间排序；不把数字按字符串排序 |
| 展示 | 允许字段出现在检索结果中，原型同时用于控制记录表列展示 | 关闭后仍可由有权限的运营人员在编辑弹窗核对原值，不是敏感权限控制 |
| AI | 允许字段参与语义索引与语义召回 | 标题、正文、摘要；不允许模型推算缺失的价格、库存或规格 |

“支持能力”与“默认开启”分开管理。页面未勾选但可点击表示支持、默认关闭；不支持的组合置灰。服务端同样拒绝越界配置。平台不向后台用户暴露 Stored、分词器、索引映射等底层参数。

类型规则：

- 单行文本允许额外开启聚合、排序；多行和富文本不提供等值聚合和排序。
- 枚举字段可额外参与关键词搜索、AI；仍须保留枚举原值与展示名称。
- 日期、数值、滑动条可开启聚合，分别按时间桶或数值区间处理。评分默认聚合，库存默认不开放聚合。
- 分类保留 ID、名称及层级路径；父类筛选是否包含子类由查询明确指定。分类字段与知识库一级/二级分类不是同一组字段。
- 地址保留已提供的国家、省市区、详细地址；没有坐标不提供距离计算，不能生成坐标或地区事实。
- 关联数据只有已授权的关联标识及展示字段可参与查询，禁止根据同名字段猜测关联关系。
- 子表单是容器，不整体设置搜索、筛选、聚合、排序、AI。详情的字段设置将子字段以“子表名称 / 字段名称”展开，按子字段类型配置。
- 媒体默认只返回链接。参考方案中的文件 AI 为后续可选能力；本次原型未提供附件解析入口，所以文件 AI 置灰。后续接入解析后，提取文本以独立字段参与搜索/AI，而不是直接索引文件 URL。
- 未识别类型默认只展示，先提示核对，不擅自按数值、日期或可搜索正文处理。
- 系统标识、企业/网站 ID、来源 ID、记录 ID、创建/更新时间用于归属和追踪，不允许删除；其中租户及权限标识不作为普通用户可自由展示的业务字段。

原型保存按钮为“保存平台配置”，成功提示“平台配置已保存”。内部保留配置版本用于追踪和重建任务，不在页面展示版本号。参数修改失败必须保留原配置，不得用提示成功代替实际保存。

默认值来源：新数据集/新字段读取平台已保存配置，按字段类型初始化。推荐分析可使用长度、基数和字段名称，但名称只是弱信号，例如“price”是字符串且有异常值时不能直接当数值入库；低基数字段在数量不超过上限且不同值比例不超过 10% 时可推荐聚合，高唯一性名称不推荐聚合。推荐结果需可追溯，不覆盖用户已有选择。

### 4. 入库前清洗与质量评估策略

与其他板块使用同一组控件，但结构化记录的判断依据不同，不沿用标题相似度来合并两条业务数据。

| 配置 | 默认值 | 结构化处理规则 |
|---|---|---|
| 隐私信息脱敏 | 关闭，未选择脱敏类型 | 开启后选择手机号、身份证号、邮箱地址、银行卡号、姓名、家庭地址；在知识副本和检索索引中脱敏，不修改业务系统原值 |
| 去重 | 开启 | 默认按来源记录标识；可切换按整行内容指纹 |
| 质量评分拦截阈值 | 60 | 0–100；低于阈值的记录不进入可检索集合，保留问题原因 |

按记录标识去重时必须包含租户、网站、来源、记录标识；同一 SKU ID 仅在对应来源内有效。可靠标识缺失时只识别同一数据集中整行完全相同的记录，不按产品名称模糊合并；不同产品/不同 SKU 即使很多字段相同也不能合并。更新已存在 ID 是更新，不是新增重复记录。

质量检查包括：必需来源标识和关联是否有效、必填业务字段完整度、类型转换结果、异常重复与解析错误。缺失标识、无权限、关系损坏等硬错误即使分数高也不能通过。可选字段为空不能当成必填错误。评分建议按完整性 40、类型有效性 30、重复与冲突 20、关联完整性 10 计算；不适用项从分母排除并归一化。各扣分原因需能定位记录和字段，运营可以从失败清单回源修复。

单独点击“保存清洗配置”保存该板块策略，不覆盖尚未保存的字段用途配置。新处理任务使用新策略；历史数据如需重检/重学应生成可追踪任务。健康度检查本身不等于学习成功，也不自动启用被运营停用的记录。

### 5. 新增知识：来源选择与上传

#### 5.1 普通应用数据源

入口“新增知识 → 选择后台页面 → 结构化数据”。保留归入内容资产时的树形逻辑，应用是可展开父节点，数据源是可勾选子节点，不另设跨应用选择向导。

每个节点显示名称、记录数量以及“新增 / 已选 / 已有 / 不可选”。勾选后下方汇总“应用 / 数据源”，可以移除、清空。折叠和搜索不丢失已选项；已有不计入本次新增，不可重复勾选。普通子表仍显示“包含某子表”选项，保持原有父子关系。

去掉每行“查看字段”和展开字段表按钮，名称直接作为跳转链接，在新页打开来源应用/数据源；产品规格名称跳到产品管理中的规格位置。原选择页面保留已选状态。研发使用来源系统返回的授权路由，不通过字符串拼接猜测实际后台地址。

重复接入以企业、网站、来源类型、来源标识和目标知识板块判断。草稿、停用关系也属于已有。同一数据源进入内容资产与结构化数据可以各有一个关系，彼此不互斥。选择某数据源接入其全部授权记录及后续新增，但不会自动接入该应用未来新建的数据源。

没有可读字段、无权限、来源已删除时不可选，并显示原因。保存时重新校验来源状态和权限，不能只依赖打开页面时的判断。

#### 5.2 产品规格

添加内容采用“应用数据 / 产品规格”两个页签。应用数据页签展示原有应用/数据源树；产品规格页签单独展示规格选择行、开启数量和接入状态。不再出现“特殊数据”的标题或角标，也不将规格伪装成应用中的数据源。两个页签共用下方已选汇总，切换页签保留选择；应用数据的搜索条件不影响规格页签。

| 展示 / 操作 | 规则 |
|---|---|
| 名称 | 产品规格，可直接跳到产品管理 |
| 数量 | 已开启规格产品数 / 全部产品数，例如 36 / 128 |
| 分子 | 当前网站、当前用户有权查看且已开启规格的产品去重数量 |
| 分母 | 同一网站、相同权限范围的全部产品去重数量 |
| SKU 数量 | 与产品数不同，不作为上述分子；解析后详情一行一个 SKU |
| 勾选 | 接入当前和后续满足“已开启规格”的产品规格，不要求先勾选普通产品数据源 |
| 0 / N、0 / 0 | 不可选，提示先在产品管理中开启产品规格 |
| 已有 | 保留勾选、禁止重复新增，后续更新/关闭使用进入接入与更新 |

“产品规格独立选择”是接入入口设计，不改变源系统中的业务关系。每条规格必须保留产品 ID 与 SKU ID。产品名称可作为关联展示字段，重量、颜色、库存等规格事实仍属于该 SKU。普通产品记录不会因为规格未开启而消失。

新增开启规格的产品进入来源新增变化；关闭规格或删除产品后，关联规格不再允许查询，移出可用记录并保留日志。自动更新关闭时，来源不再有效的数据也不能继续作为有效事实回答；变化详情与手动同步负责后续索引清理。用户在知识库停用某 SKU 不会关闭原产品的规格开关，源业务更新也不能自动恢复用户停用状态。

未来新增需独立接入的业务类型，使用具体业务名称扩展同级页签，由来源提供名称、能力条件、数量口径、授权跳转路由和稳定接入标识。不同类型可有自己的数量副文案，不强迫所有特殊数据都使用产品数比例，不另开一套选择流程。

#### 5.3 上传文件与元数据

“上传文件”可选板块仅为：文档知识、问答知识、结构化数据；取消网络知识。网络知识仍通过“学习外部网址”接入；历史网络文件资产按既有方式维护，不因取消新增入口而删除。

结构化文件沿用原有本地上传和对象存储交互。支持 XLS、XLSX、CSV、JSON、JSONL；本地每次一个非空文件，最大 100 MB。对象存储也必须在服务端执行同样的格式、可读性、大小检查，不能只根据名称判断成功。

选择结构化数据后，上传方式右侧复用问答知识的“下载模板”文字入口，提供 XLSX、CSV、JSON、JSONL 四个直接下载链接，本地上传和对象存储模式均可下载，不增加独立说明卡片。Excel 模板统一提供 XLSX；已有 XLS 文件继续兼容上传，使用同样的首行字段名结构。

模板中文名统一为“结构化数据导入模板”加对应扩展名。四份文件采用同一组售前咨询示例：记录编号、产品名称、材质、重量（kg）、起订量（件）、交付周期（天）、更新日期、产品说明。Excel/CSV 首行是字段名，JSON 是对象数组，JSONL 每行一个对象。数字保留数值类型，日期使用明确格式，编号保留文本。模板不加入标题行、说明行或额外说明工作表，以免被当作数据入库；示例列不是平台固定字段，用户可按业务增删，上传后仍按实际字段识别。

| 格式 | 入库结构 | 异常处理 |
|---|---|---|
| Excel / CSV | 首行为字段名，后续每行一条记录 | 空表头、重复表头、空文件明确报错；多工作表明确选择处理范围后再入库 |
| JSON | 顶层对象数组，每个对象一条记录 | 不是对象数组时提示格式错误 |
| JSONL | 每个非空行是一个对象 | 返回行号、字段和错误原因，不静默丢行 |
| 数组 / 嵌套对象 | 已识别子表按父子结构保留，字段配置展开到子字段 | 未支持的嵌套形态提示修正，不压成无法区分归属的长字符串 |

字段名、类型与单位来自实际文件；不能把产品、颜色、重量等示例列硬编码给所有文件。编号和 SKU 即使只包含数字，也需保留前导零；不确定类型按保守规则处理并提示核对。日期区间、分类树、地址对象、关联数据采用参考方案的数据结构，不丢失层级和关联标识。

元数据沿用当前新增知识表单：所属行业、知识库类型必填，后台用户不能选择行业知识库；其余字段保持原有选填与“未指定”规则。一级/二级分类用于组织和 Skill 范围，不替代业务字段。保存与保存并创建均保留原有草稿流程，不因本次增加结构化数据而自动发布。

每个数据源/特殊来源生成一个数据集草稿；每个文件生成一个数据集草稿。解析完成前记录区域为空，不展示与该来源无关的假数据。

| 分页 | 原型每页 10 条；全选筛选结果覆盖全部匹配记录，不只当前页 |

详情保留结构化表格，使用与其他知识详情一致的紧凑搜索栏、状态标签、灰底停用行和小尺寸按钮；选中记录后才展示批量操作，避免常驻一排禁用按钮。记录表采用限高滚动区。点击记录链接、单元格或“编辑”，打开与其他知识解析块一致宽度的编辑弹窗，底部使用“取消 / 确认”。原始字段只读；分组为“原始数据”和“知识信息”。

知识信息包括关键词、可能问题、标签、启用开关。关键词/标签可多项，可能问题可多个；单条编辑复用其他知识解析块的标签式输入：点击加号或回车添加，点击删除图标移除；批量添加标签仍可每行一项或逗号分隔，保存去除空值及重复项。批量标签是追加并去重，不覆盖原标签。取消弹窗不保存修改。状态筛选或搜索条件改变后清空旧批量选择，防止误操作；分页保留选择。

原业务字段在应用后台修改，文件字段通过更新原文件修改；不要在该弹窗允许任意改业务值。后台来源保存修改后实时进入知识更新流程；更新记录保留人工设置的启停及关键词、问题、标签。文件更新若无可靠键，不能按行号强行继承上一文件的编辑结果，应提示重新核对。

行 ID 必须稳定：应用记录使用来源记录 ID，规格使用来源产品 ID 与 SKU ID，上传记录由服务端分配记录 ID。索引重排、筛选、翻页不能改变身份；生产不能用数组下标作为记录 ID。原型静态样例的临时 ID 仅用于演示。

启用是运营意图，不保证立即可检索。实际可用必须同时满足：来源有效、接入继续使用、数据集启用、行启用、质量合格、学习成功、用户有权访问。停用后立即从所有检索出口排除，仍保留数据和历史。草稿或停用数据集里的行即使启用，也不能越过上级状态。质量问题、无权限、来源已删除不得被批量启用绕过。

编辑已启用记录的关键词、问题、标签并保存后，提交受影响记录的学习/索引更新任务，不必再点立即同步。原始内容不变的任务保留数据版本；学习完成之前不返回半更新索引，停用意图实时生效。后台同步不能覆盖人工停用。

#### 6.3 字段设置弹窗

表格为“字段、类型、搜索、筛选、聚合、排序、展示、AI、设置来源”。类型和名称只读，六项能力为复选框；设置来源显示平台默认或自定义。非法能力置灰，子表字段以完整路径显示。

保存仅影响当前数据集，不更改原网站应用设置，也不影响其他数据集。关闭“展示”后记录表相应业务列隐藏；运营仍可打开弹窗核对原始内容。字段读取权限被撤销时，无论展示、搜索、AI 是否开启均立即不可用，不允许以管理员配置逃逸来源权限。

“恢复平台默认”仅调整弹窗草稿，保存才生效；取消恢复原有配置。新字段使用最新平台默认，旧字段的自定义维度保留；字段类型改变后重新校验能力，暂时隔离不再支持的配置并提示处理。

管理员在记录表中搜索所有授权字段用于排查，与面向智能体/访客的“搜索”能力不同。六项能力控制检索服务及用户结果，不要求管理员因为关闭某字段的搜索就无法排查该字段。AI 关闭表示不参与语义索引，不等同于不能随合法结构化查询结果展示给智能体；敏感字段必须通过权限或脱敏控制，不能只关闭 AI。

### 7. 运营操作示例

#### 示例 A：接入产品规格，用于售前选型

1. 在产品管理中对需要使用规格的产品开启规格。本例当前网站共 128 个产品，其中 36 个开启规格。
2. 新增知识选择“后台页面 → 结构化数据”，在“产品规格”页签看到“产品规格：36 / 128”，勾选后变为已选。普通产品数据源可以不选。
3. 填写所属行业、企业业务知识库，并按需要选“产品与资源 / 产品信息”，保存草稿，完成学习后启用。
4. 进入详情，每行对应一个 SKU，展示所属产品、SKU、颜色、包装大小、重量等当前网站实际字段。
5. 右上角字段设置：颜色/包装大小使用枚举筛选与聚合，重量使用数值筛选、排序、展示，名称使用搜索、展示、AI。
6. 打开某行，添加关键词“红色、小包装”、问题“经典款红色小包装的重量是多少？”、标签“售前选型”。不在知识弹窗更改重量。
7. 客户问“红色小包装、重量不超过 1.5 kg 的有哪些”，条件必须落在同一条 SKU 上；不能把红色大包装的重量拼给小包装。不命中时明确没有匹配记录。
8. 一条规格信息待核实时单独停用，其他 SKU 继续可用；来源更新后保留停用意图。业务错误去产品管理修复，再恢复使用。

#### 示例 B：接入非产品应用

展开“采购招标 → 中标公告”并选择数据源，点击名称可直接打开来源，保存后按该源的公告标题、中标单位等字段展示。标题默认搜索、展示、AI；发布日期按日期规则可筛选排序。不会出现颜色、SKU、包装大小等产品列。来源为已有时不能重复新增，去接入与更新管理。

#### 示例 C：上传 Excel，批量治理记录

上传规格参数.xlsx，首行包含“产品编号、SKU、产品名称、颜色、包装大小、重量、材质”，保存后按实际类型解析。发现两行重量为空时，先筛选对应记录，勾选后批量停用并追加“待核对”标签；回源文件补齐事实，更新文件并重新处理。使用稳定 SKU 匹配原记录，保留人工标签与停用状态，核对后再批量启用。颜色列默认筛选与聚合；重量默认数值筛选、排序，不能按文本比较“10”和“2”。

原型可从“产品规格参数.xlsx”样例查看一条启用、一条停用及三条记录的批量处理。JSONL 样例提供同样的表格和记录弹窗，不新做另一种详情交互。

#### 示例 D：平台调整默认值、客户覆盖

平台将“单行文本”的聚合打开并保存。此后新数据集的单行文本使用新默认值；已有数据集不突然改变。客户发现产品名称几乎每条不同，在本数据集字段设置中关闭名称聚合，同时保留材质聚合。后续平台再次改默认值，不覆盖这一客户选择；只有客户主动恢复平台默认并保存才重置。

### 8. 研发落地与验收

#### 8.1 数据流与职责边界

来源连接/文件解析 → 识别真实字段与父子关系 → 平台默认配置初始化 → 清洗与质量检查 → 生成数据集及稳定记录 → 索引或参数化查询 → 按六项用途和授权返回结果。

业务字段、系统追踪字段、知识增强信息分开存放；知识库分类和适用对象仍挂在数据集上。记录继承上级范围，并维护独立启停。输出给智能体时必须带数据集、来源、记录标识、更新时间及允许返回的字段；来源缺失、空值不得补成模型编造的事实。

检索只读；数值/日期条件参数化，不能让模型提交任意 SQL。过滤、聚合、排序能力按类型校验。聚合不能基于已截断的 10 条返回记录伪装成全量统计；应在有权访问且符合条件的完整集合上计算。超过返回上限提示未完整返回。父子条件必须由同一条子记录满足，未经配置不做跨数据集关联。

索引任务记录配置版本、来源结构版本、操作者、触发原因、受影响范围、开始结束时间及失败原因。批量操作由服务端按筛选快照和排除 ID 执行，并返回成功、失败、跳过数量；权限或来源状态在操作时变化应返回部分失败清单。重复提交幂等，关闭接入/停用记录后迟到任务不得重新启用。

#### 8.2 验收要点

- 平台页有完整类型默认矩阵及有效默认值，不出现客户专属产品字段；后台用户没有知识板块权限。
- 结构化板块包含与其他板块一致的清洗区，结构化去重不使用标题相似度。
- 新增保持应用/数据源树，产品规格使用独立页签；显示 36 / 128 而不是 72 个 SKU / 128 产品；0 开启产品不可选。
- 数据源名称直接跳转；没有逐项查看字段按钮；新页打开不清空原已选范围。
- 上传文件没有网络知识；本地和对象存储的服务端校验一致。
- 不同应用与文件产生不同字段表；特殊规格一行一个 SKU，普通产品不会自动包含规格。
- 单行弹窗、批量启停、批量追加标签、分页与全选结果能闭环；手动停用不被同步覆盖。
- 六项字段设置读取平台默认；取消、保存、恢复默认结果正确；平台变更不覆盖已确认配置。
- 上级状态、行状态、质量及来源权限共同限制检索，不能仅通过行启用绕过。
- UI 未展示索引或版本实现说明；任务追踪与版本记录在研发实现及日志层保留。

#### 8.3 原型与真实接入的边界

本次原型已实现配置保存、树形选择、产品规格页签、记录表/弹窗、批量操作、字段用途与展示列联动；数据均为内存示例，刷新会回到样例。不代表文件已经真实解析、推荐引擎已经分析数据、平台策略已经下发到客户或索引已经重建。

来源系统不在本原型工程中：名称跳转当前使用独立来源预览页承接，保留新页打开的交互；研发须替换为真实应用/数据源或产品管理授权路由，不将来源预览页作为新的业务维护后台。真实文件解析、多工作表选择、来源权限、跨页批量查询、任务队列、索引生效和服务端持久化由研发接入，上述产品规则为实现与验收依据。

## 一、阶段定位与范围

知识库一期已结束，一期文档作为已完成阶段的交付基线保留。本文件承接本次新增的接入、同步、内容更新与健康度维护需求，后续相关调整归入二期，不追加到一期验收范围。

二期当前目标是让用户按前台栏目、后台应用维护持续学习范围，查看来源新增和删除变化，并按各知识板块的特点更新内容、处理健康度问题。栏目内容修改由发布事件实时同步，不在栏目层统计修改数量。

本次原型已调整，尚不代表二期研发实现或验收完成。原型入口：`/knowledge-config/sync`；新增接入入口：`/knowledge-config/catalog/new`。

## 二、接入与更新页面

入口为左侧“数据接入 → 接入与更新”，沿用 `/knowledge-config/sync` 路由。页面分为“接入来源”和“知识更新与体检”两个页签，企业用户仅维护本企业数据。

**接入来源**按前台站点栏目、后台应用或数据源展示，一行代表一个应用/数据源在指定知识板块的学习关系，不能用一篇文档或一个切片代替整栏目。前台页面只归入内容资产；后台页面可归入内容资产或结构化数据。新增知识沿用前台树形结构和后台应用选择，并在新增时设置“学习启用”；接入与更新页面只负责管理更新方式及是否继续使用。

| 字段 | 定义 |
|---|---|
| 知识资产 | 主标题使用关联知识资产的名称，与知识资产目录同一资产 ID、同一名称并联动更新；点击进入该资产详情。一个来源关联多项资产时显示前两项并提供查看全部入口；来源方式和完整应用/数据源路径作为次级信息。未生成资产时显示“尚未生成知识资产”，不把来源名称冒充资产标题 |
| 知识板块 | 前台页面固定为内容资产；后台页面可选择内容资产或结构化数据；同一来源进入不同板块时分别维护 |
| 已入库 | 该接入关系已经生成的知识总数，不等于当前分页数量或切片数 |
| 使用状态 | 展示并管理该接入是否继续使用。关闭后保留接入关系、变化记录和任务日志，但停止检测和同步，并停用由该关系生成的知识 |
| 变化详情 | 仅展示最近检测到的新增和来源删除条目，并可查看名称、来源路径和检测时间；内容修改不在栏目层计数 |
| 自动更新、更新频率 | 自动更新开关以及实时、每小时、每日、每周频率；关闭后继续检测变化，但不自动处理新增和删除 |
| 最近检测、最近学习、下次更新 | 分别显示最近一次变化检测、最近一次成功学习和预计下次执行时间；实时模式显示“内容发布时” |
| 健康度 | 当前栏目下已入库知识的聚合健康度，用于定位需要维护的栏目 |
| 状态 | 正常、待手动更新、同步中、同步失败、已停止；与单条知识生命周期分开表达 |

操作与规则：

1. 系统持续检测栏目条目的新增和删除，同时在最近检测时间旁提供“检测变化”按钮，允许用户主动检查。检测中禁用重复操作，不执行同步或学习；成功更新检测时间及新增/删除详情，失败保留上次成功结果并写入日志，不得把无法访问认定为全部删除。已关闭使用或同步中的来源不可检测。
2. 栏目内容修改由前后台发布事件实时同步。栏目接入层不知道正文具体修改数量，因此不展示“修改条数”；每次实时处理的结果、时间和失败原因写入更新日志。
3. 变化详情只承担告知作用。自动更新开启时，新增和删除按配置频率处理；自动更新关闭时继续检测并展示变化，用户可点击“立即同步”手动处理。
4. 接入列表保留“查看知识、立即同步、任务日志”操作，并提供“使用状态”用于关闭或恢复已有接入。新增时的“学习启用”不在此重复配置。立即同步不能替代文档知识的文件更新，也不能绕过学习中状态重复提交。
5. 用户可直接修改自动更新开关和更新频率。频率变化需更新下次执行时间并写入日志；实时模式的内容修改仍以发布事件为准。
6. 健康度显示栏目内知识的聚合结果。用户从低健康度栏目进入关联知识处理具体问题；健康度检查本身不触发学习。
7. 关闭“使用状态”时展示应用/数据源及受影响数量：停止变化检测、自动更新和实时内容学习，同时停用此学习关系生成的知识，保留接入关系、内容、变化记录和日志。执行中的任务结果不得在关闭后重新启用知识。
8. 恢复使用后恢复检测与学习，并恢复因该关系关闭而停用的条目；用户此前单独停用的知识继续停用。来源未变化的知识保留人工编辑结果。
9. “查看知识”跳转知识资产目录，并携带来源和板块过滤条件。知识资产目录提供“应用/数据源”筛选，并在知识名称下显示完整来源路径，解决后台页面导入后大量同类名称难定位的问题。

批量管理：两个页签均提供单选、全选筛选结果与清空，切换页签或筛选条件时清空选择。接入来源支持批量检测变化、立即同步、开启/关闭自动更新、修改更新频率、关闭/恢复使用。执行前弹窗列出选中项、可执行项及跳过项；关闭使用额外提示受影响知识数量并确认。检测中、同步中的条目跳过；已关闭来源仅可恢复使用。执行时服务端重新校验权限与状态，结果显示成功、失败、跳过数量，各来源写独立日志；批量检测失败不会清空已有变化结果。原型显示全部已加载匹配项，正式分页后的全选由服务端按筛选快照执行，不只选当前页。\n\n知识更新与体检的首列表头也统一为“知识资产”，直接使用目录资产名称。该页签支持批量检测健康度，草稿和学习中跳过；保留未参与本次检查的已有评分。不批量替换不同知识的文件，不给文档类知识增加立即同步操作。\n\n**知识更新与体检**沿用知识资产字段和五种生命周期状态，按板块与实际来源提供维护入口。栏目来源可在“接入来源”执行立即同步；文档、问答等单条知识按内容维护方式更新，不提供重复的立即同步操作。

| 知识板块 | 内容维护方式 | 健康度检查与下一步 |
|---|---|---|
| 文档知识 | 更新原文件，保留资产 ID、分类、适用范围；局部问题进入详情编辑切片 | 检查文档有效期、缺失正文和异常切片；更新后自动学习，完成后复检 |
| 问答知识 | 编辑标准问题、富文本答案与相似问法；文件导入支持更新数据文件 | 检查空答案、重复问法、人工审核与答案有效性；保存答案后自动学习 |
| 内容资产 | 在前后台原栏目修改并发布，发布事件实时同步；同步结果写入日志 | 检查来源可访问性、缺失内容、路由和正文时效；进入对应接入关系处理 |
| 结构化数据 | 业务接入检查来源与字段；上传型更新 CSV、XLSX、JSON、JSONL | 检查字段完整性、重复记录、连接与数据新鲜度；实时查询型不强制走切片学习 |
| 网络知识 | 检查网址、修改来源或正文后重新抓取；文件导入型更新原文件 | 抓取失败先修复网址或访问问题，不能只重跑已有切片 |
| 行业知识 | 企业维护自己的导入副本；可编辑正文与切片，平台资料另行导入 | 检查行业匹配、资料有效性和内容质量，平台变化不自动覆盖企业副本 |

健康度检查本身不触发学习；学习中展示“待检查”和任务入口，禁用重复内容更新。修复完成后重新计算内容质量、时效、复用及反馈指标，不把点击检查或任务完成等同于健康度满分。低复用仅给出使用范围建议，不要求重新学习；来源异常进入来源管理，内容异常进入编辑或替换文件。

原型说明：栏目计数、变化详情、健康度和更新日志为预设聚合示例，资产目录仅有部分示例知识。文件替换原型演示格式/大小校验和状态变化，真实上传、解析、实时发布事件、差异详情及任务结果由后端接入后实现。


## 三、内容保存与学习状态

替换原文件、修改已启用知识的正文或切片并保存后，自动提交学习任务，状态进入学习中，不要求用户再次点击同步或重新学习。仅调整需要重建索引的分类、时效等元数据时，沿用待更新流程。草稿或停用知识编辑后保持原检索状态，不因编辑自动启用。学习任务复用已有状态和进度，重复点击不得生成并行任务。新学习版本成功前按既有规则使用上一成功版本，避免返回半更新内容。


## 四、页面联动与权限

- 新增知识保留前台树形结构和后台应用选择；前台页面只进入内容资产，后台页面可进入内容资产或结构化数据。新增页面提供“学习启用”，保存后按该设置创建学习关系；已有关系通过“管理已有接入”维护更新方式或关闭使用。
- 知识资产目录承接单条知识编辑、停用和详情查看；按栏目跳转时携带来源与板块条件，并提供清除来源筛选入口。
- 概览中“内容过期 / 待更新”跳转到“知识更新与体检”，操作文案为“去维护”。
- 平台账户按授权范围操作；后台用户仅能查看和操作本企业数据，服务端需校验企业、来源、资产归属。
- 本期调整替代旧“同步状态”页面；一期历史描述保持不变，二期新增行为以本文件为准。

## 五、验收要点

1. 一个栏目关联多条知识，已入库及新增、删除数量按该接入关系全量统计，不能使用列表当前页数量代替，也不得展示无法准确计算的内容修改数。
2. 新增和删除变化自动检测；自动更新关闭时变化持续展示，立即同步可处理待更新内容。内容修改随发布事件实时同步，并可在日志核对结果。
3. 关闭学习后，相关知识停止检索且不接收更新，接入关系和历史记录保留；重新开启时不误启用此前单独停用的知识。
4. 查看栏目知识能正确筛选来源与板块；目录支持选择应用/数据源，列表展示完整来源路径，用户可清除筛选返回全部知识。
5. 更新文档校验格式、非空和 100 MB 大小上限；启用内容保存后进入学习中，草稿、停用内容保留原状态。
6. 切片保存后正确更新内容与学习状态，学习中不能重复提交；健康度检查不会再次触发学习。
7. 接入来源保留自动更新、更新频率、最近/下次更新、健康度、立即同步和日志；六类知识板块的单条内容维护入口符合各自来源及内容形式。
