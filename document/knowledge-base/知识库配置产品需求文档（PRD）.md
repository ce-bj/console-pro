## 一、文档说明

**这份文档记录什么**：知识库配置模块的研发需求边界——页面、字段、交互、指标口径和业务对象。本文以知识库体系、检索方案和现有知识库 PRD 为内容依据，将已确认的页面交互收敛为可实现、可测试的规则、状态、接口语义和验收标准，不是愿景稿。

**和另外三份文档的关系**：

| 文档 | 定位 | 与本文档的关系 |
|---|---|---|
| 《知识库体系架构方案》 | 内容组织的设计源头：6 大板块怎么分类、生命周期、健康度、治理 | 本文档里"知识板块""健康度""门禁检查"等概念均出自该方案，本文档只取其中**已经做成界面**的部分 |
| 《通用检索系统产品方案》 | 检索能力的设计源头：双模检索、5 类数据源、参数体系 | 本文档"检索策略""问答测试"对应该方案的落地 |
| 《rag方案（调研）》 | 全链路 RAG 深化调研 | 影响了切片解析方式（自动元数据/关键词/问题提取等字段，参考 RAGFlow） |

**读者**：研发（对照原型排期开发）、测试（对照功能清单验收）。

**目标用户**：网站运营/内容运营人员，非技术背景。所以整个模块的设计原则是"能上传/能改字段就行"，复杂的解析算法、检索参数系统给出**推荐默认值**，藏在"配置"里，日常不需要碰。

## 二、产品定位与目标

网站配了智能客服和内容生成智能体后，两者都要"读知识"才能干活——客服要引用知识回答用户，内容生成要引用知识写文案。这些知识散落在前台页面、文件、外部网页、数据库里，格式不一、更新方式不一。

**知识库配置**要解决的问题：让运营人员用一个后台，把这些分散的内容**统一管起来**——知道有什么知识、知道好不好用、知道怎么让它更好用，而不需要理解背后的向量库/分块算法/RAG 是什么。

一句话定位：**知识库配置 = 网站知识的中央管理后台**，管内容、管处理方式、管效果。

### 3.1 知识库挂在哪一层：客户 → 产品组 → 站点

平台是多租户的。要回答"这套知识库是谁的、几个网站共用"，必须先说清三层归属关系——**知识库挂在产品组（product_group_id）这一层**，不在客户层，也不在单个网站层。

```
customer_id（客户）
   │  客户在平台其它场景（注册、企业认证、其它产品）已经登记过所属行业
   │  行业信息在此沉淀，可被其名下产品继承
   │
   ├─ product_group_id（产品组 = 一次门户产品的购买）
   │     │  ★ 知识库配置模块作用在这一层：一个产品组一套知识库
   │     │  · 创建产品组时，从 customer_id 带入已登记的行业作为默认值
   │     │  · 本模块的知识资产、板块配置、元数据规范、健康度、体检、行业配置
   │     │    全部以 product_group_id 为边界，组内共享、组间隔离
   │     │
   │     ├─ site_id（站点产品 A · 中国大陆站 · 简体中文）
   │     ├─ site_id（站点产品 B · 北美站 · 英语）
   │     └─ site_id（站点产品 C · 东南亚站 · 多语种）
   │           站点是客户面向不同地区购买的网站产品，
   │           共用同一套知识库，检索不受站点或语言限制
   │
   └─ product_group_id（另一次购买 = 另一套独立知识库）
```

三层各自的职责与约束：

| 层级 | 标识 | 在本模块中的作用 |
|---|---|---|
| 客户 | `customer_id` | 行业信息的**源头**。客户可能在平台其它场景已选过行业，购买门户产品时带入产品组作为默认值，避免重复填写。客户层不直接持有知识库。 |
| 产品组 | `product_group_id` | **知识库的归属边界**。一个产品组一套知识库：知识资产、6 个板块的处理配置、元数据规范、敏感词库、健康度权重、体检结论、企业行业配置（主行业 + 额外行业）全部按产品组隔离。跨产品组不可见、不共享、不互相影响。 |
| 站点 | `site_id` | 客户面向不同地区/语言购买的网站产品，**多个站点共享所在产品组的这一套知识库**。站点只在「元数据规范 → 门户网站范围」和知识资产的「适用站点」字段上体现——用来限定某条知识或某组配置对哪些站点生效，不构成独立的知识库。 |

由此产生几条必须遵守的规则：

1. **本模块所有接口都隐含产品组上下文**，服务端按当前登录用户所属的 `product_group_id` 过滤，前端不传也不允许跨组查询。文档中出现的所有统计口径（知识总数、板块健康度、召回率、体检结论计数等）都是"本产品组内"的口径。
2. **行业继承是"带入默认值"，不是"强绑定"**。产品组创建时从客户带入行业，之后在「知识板块 → ⑥行业知识 → 行业知识配置」里由运营确认或修改（见 §7.2.1）；客户层后续改行业不回写已存在的产品组。
3. **站点不拆分知识库**。同一产品组下不同语言/地区站点检索同一份知识，语言只作为知识的元数据标签（`language`），不作为检索隔离条件——这也是「元数据规范」页底部那句提示的由来。
4. **换产品组等于换知识库**。运营切换产品组后，看到的是完全另一套内容与配置，不存在"部分继承"。

> **术语对齐**：本文档其余章节沿用的"当前客户""客户后台"等表述，指的都是**当前登录上下文所在的那个产品组**（一个客户可能有多个产品组）。凡涉及数据边界的地方，一律以本节的 `product_group_id` 为准；文中"不做跨客户看板""只看当前客户自己的数据"等约束，同样按产品组粒度落实。平台侧跨客户/跨产品组的聚合视图在 N12「平台运营看板」承载，不在本模块。

## 五、用户使用流程图

### 流程 A · 日常内容录入与维护（最高频）

```
进入「知识资产目录」
        │
        ▼
点「+ 新增知识」──┬─► 上传文件（多选，一次建多条）
                 ├─► 外部网址（可加多个，支持"来源分组"聚合展示）
                 ├─► 对象存储（可勾选"同时归入其它板块"）
                 └─► 从前台页面选择（只列③结构化数据/④内容资产两个板块的页面，按站点/导航树逐级展开勾选，支持整个分支批量选中，归属可同时勾选两个板块）
        │
        ▼
内容自动落入对应「知识板块」──（板块已配好处理方式，无需再选解析参数）
        │
        ▼
确认文档级元数据：知识标题、知识库类型、行业/企业、一级/二级分类、
内容形式、有效状态、来源；适用对象和语言按需填写
        │
        ▼
可选：继续编辑门户网站、标签、业务用途、场景等现有元数据
也可查看/补充前台页面路由、导航路径、页面数据类型、结构化字段
或归到「知识目录」文件夹分组，方便按业务口径归类
        │
        ▼
点条目进「知识详情」──┬─► 看解析出的切片对不对（原文 vs 切片双栏对照）
                     ├─► 切片可加关键词/问题/标签、启用禁用、批量操作
                     └─► 看健康度、门禁检查有没有卡住
        │
        ▼
若来源是前台页面/外部网址/对象存储 → 会自动保持同步，去「同步状态」看运行是否正常
```

③结构化数据支持两条录入路径：一是直接上传 JSON/JSONL/CSV/XLSX 等结构化文件（内容形式固定为"数据"，按记录/字段解析，不做向量切片，可在上传时填写字段名列表），二是"从前台页面选择"读取前台页面绑定的实时数据字段；两条路径互不排斥，运营按数据来源选择对应 Tab 即可。④内容资产（图文详情、专题、活动页等）本身就是前台页面内容，不提供"上传文件/外部网址/对象存储"这类通用录入方式，新增时直接跳转到"从前台页面选择"，不展示通用上传 Tab。"从前台页面选择"这个选择器的树只列③结构化数据/④内容资产两个板块的页面，归属只给这两个 checkbox，可同时勾选，不支持挂到其它 4 个板块。①文档知识板块的上传仍复用现有的上传+解析流程（按段落切片），与③结构化数据的按记录/字段解析是两条独立路径，互不影响。

本流程中的“知识板块”和“知识库类型”是两个独立维度：知识板块仍为现有 6 类处理形态，决定解析、切片和检索方式；知识库类型表示业务归属与复用范围，取值为“行业知识库、企业公共知识库、企业业务知识库”。选择或修改知识库类型、行业、企业及分类路径，不自动改变知识板块。行业知识库必须选择所属行业，不要求所属企业；企业公共知识库和企业业务知识库必须选择所属企业，所属行业可由企业信息继承并在文档上展示。

“知识标题”沿用当前资产名称，不再新增第二个含义重叠的标题字段。“正文或附件”是文档级权威内容载体；非结构化内容学习后形成切片集合，结构化数据仍按字段和数据源查询，不进入向量切片流程。

### 流程 B · 板块处理效果调优（低频，出问题时）

```

        │
        ▼
发现答非所问 / 没召回 ──► 判断是内容问题还是参数问题
        │                          │
        ▼ 内容问题                  ▼ 参数问题
  去「知识资产目录」          去「知识板块」→ 点 ⚙️ 进入该板块配置
  补充/修正对应知识                  │
                                    ▼
                     调整「切片解析方式」（分块粒度/PDF解析器/自动关键词提取…）
                     或「入库前清洗与质量评估策略」（隐私脱敏/去重/打分阈值）
                     或「检索策略」（向量权重/阈值/TopK/Rerank）
                                    │
                                    ▼
                          保存配置 → 已入库内容需「重新学习」才应用新配置
                                    │
                                    ▼
                          回「问答测试」重新验证
```

### 流程 D · 目录内知识健康体检（内容库存体检）

```
「知识资产目录」
        │
        ├─► 顶部「知识健康体检」问题分布条已按当前内容实时算好各结论条数
        │      待修复缺陷：全部缺陷 / 需更新 / 缺路由 / 缺字段
        │      运营信号：无命中 / 低复用   ｜  健康
        │
        ├─► 点任一结论 → 列表立即只剩这批知识（无需先勾选、无需等待）

        │
        └─► 修复即时重算结论与健康度，并写入「修复流水」
        │
        ▼
「对话质量运营」继续负责召回、回复、准确率、满意度、盲区等对话侧指标
```

## 七、功能描述

### 7.1 总览（概览）

运营人员进入模块的第一屏，回答"现在整体情况怎么样、我下一步该干什么"。4 个 KPI 卡给全局印象；"需要处理"列表把待评估、低健康度、过期待更新、覆盖盲区四类事项聚合成待办，每条都能一键跳到对应页面处理，不需要自己去各页面翻找。板块分布用横向条形图对比 6 个板块的知识量和健康度，点击某一行直接跳到「知识资产目录」并预置该板块筛选。

4 个 KPI 的口径固定：知识总数为未删除资产数；已发布上线为已发布且启用检索的资产数；待处理为待评估、待更新、低健康度（健康度低于 60）三类待办的合计，允许同一资产同时计入多个待办；平均健康度只计算已有健康度的资产，没有可计算资产时显示 `--`。概览跳转只带入筛选条件，不自动修改资产、不自动执行修复动作。

### 7.2 知识板块

**列表页**是 6 类知识处理方式的说明书：每张卡片用大白话解释"这类知识怎么处理、怎么检索"，不出现分块算法、向量库这类术语。卡片本身点击进入资产目录（内容），卡片右上角单独一个 ⚙️ 图标进入配置（处理方式），两个入口职责分开，避免运营人员在"看内容"和"改参数"之间迷路。

**配置页**是唯一改处理方式的地方，分三段：

- **切片解析方式**：参考 RAGFlow 的通用切片方法（任务页面大小、PDF 解析器、文本块大小等），每个配置项都带 `?` 提示解释含义和影响；"自动元数据"额外提供「设置」入口，弹窗里可以像 RAGFlow 一样定义要自动生成的自定义字段（名称/描述/类型），分「生成」（用户自定义）和「内置」（系统固定，如标题、来源、创建时间）两个标签页。**一个板块可以按「内容形式」配多套切片方式，不再是一板块一种，详见 §7.2.2。**
- **入库前清洗与质量评估策略**：隐私信息脱敏（按勾选的隐私类型识别并替换为占位符）、去重策略、质量打分拦截阈值——这是内容进库前的处理关卡，对应架构文档里的门禁检查在板块层面的可配置化。该段是板块级配置，不按内容形式细分。
- **检索策略**：向量权重、相似度阈值、TopK、Rerank、Embedding 模型，系统给出行业推荐默认值，页面上直接提示"仅在出现具体召回问题时再调整"，降低误调的可能。该段同样是板块级配置。

配置页不展示条数、状态分布、同步健康度等只读监控信息——editing 内容与查看内容概览始终只在「知识资产目录」做，避免同一件事有两个入口造成数据不一致的心智负担。

结构化数据板块（③）特殊处理：不进向量库、不做切片，直连数据库查询，因此配置页对这个板块跳过上述三段表单，改为展示说明文字 + 「MCP 动作」勾选清单，详见 §7.2.3。

其余板块保存配置时需校验数值范围：任务页面大小不少于 1，文本块大小为 64–2048 且按 64 递增，图像/表格上下文窗口为 0–5，自动关键词/问题提取数量为 0–10，向量权重和相似度阈值为 0–1，Top K 为 1–20。配置保存只影响后续入库；已有内容必须重新学习成功后才应用新配置。

#### 7.2.1 ⑥行业知识板块：企业行业配置（主行业 + 额外行业）

行业知识库由平台统一维护、跨全部客户共享，企业侧不能直接录入，只能**圈定自己可以取用哪些行业**，再从平台行业库导入到本产品组的知识资产目录（导入交互见 §7.3）。这个圈定动作就在⑥行业知识板块配置页顶部的「行业知识配置」卡片完成。

**行业体系是两级的**：一级行业 → 二级行业，由平台维护，企业侧不可增删。选择时**两列联动**：左列选一级行业，右列自动加载该一级下的二级行业，选满一组算完成一个行业。切换一级行业会清空已选的二级，避免残留上一个一级下的值；个别没有二级的一级行业（如「其他」），只选一级即算完整。

**一次配置包含一个主行业和最多 2 个额外行业**：

| 类型 | 数量 | 含义 |
|---|---|---|
| 主行业 | 1 个，必填 | 本企业所属行业。产品组创建时从 `customer_id` 带入默认值（见 §3.1），由运营确认或修改。 |
| 额外行业 | 0–2 个，选填 | 不是企业所属行业，而是**为了取用其它行业的行业知识**而额外圈定。例如主行业是「家居建材 / 全屋定制」，额外加「材料化工 / 涂料油漆」以取用上游材料知识。 |

约束与提示：

- 合计最多 3 个行业（1 主 + 2 额外）；主行业与额外行业不能重复。
- **一年内最多更改一次**。首次配置不受冷却期限制，保存后开始计时；冷却期内「更改行业」按钮置灰，并显示下次可更改日期。
- 更改行业需二次确认，明确告知：不再属于新选行业的行业知识库内容**将无法从平台再次获取更新，历史已导入内容保留、仅不再同步新版本**。这是"请谨慎选择"的具体后果，不能只写一句模糊警告。
- 未配置行业时，卡片显示"尚未配置行业"，按钮为可点击的「配置行业」；配置完成后按钮变为「更改行业」并受冷却期约束。

#### 7.2.2 按内容形式细分的切片解析方式

**背景问题**：原设计是"一个知识板块用一种切片方式"，粒度太粗。同样是①文档知识，一份制度政策和一份产品手册的理想切法完全不同——政策要按条款切、手册要按章节切，强行共用一套参数必然有一方被切坏。

**解决方式**：板块下的切片配置从"一套参数"改为"**按内容形式挂多套规则**"。内容形式复用「元数据规范」页已有的 `content_format` 枚举（文章/政策/指南/FAQ/数据/案例/通知/手册/其他），不新造字段。

规则模型：

| 规则 | 说明 |
|---|---|
| 「通用」 | 每个板块**必有且仅有一条**，不可删除。板块原有的那套参数即为它的初始值。所有没有单独配置内容形式的知识都走这条。 |
| 某内容形式的专属规则 | 0..N 条，由运营按需新增。命中同名内容形式的知识优先走这条。 |

交互：切片解析方式卡片顶部是一排内容形式芯片，形如 `[通用 默认] [政策 ✕] [＋ 新增内容形式]`。点芯片切换当前编辑对象，下方全部切片参数（含"自动元数据"的字段 schema）作用于选中的那条规则。芯片下方一行文字说明当前编辑的是兜底规则还是某内容形式的专属规则，避免运营改错对象。

- **新增**：点「＋」弹窗选一个尚未配置过的内容形式（已占用的自动从下拉中排除；「通用」是保留值不出现在列表里）。新规则**以「通用」当前参数为起点**，运营只需改差异项，不必从零配一遍。
- **删除**：非通用规则可在芯片上点 ✕ 删除，删除前确认并明确告知"该内容形式的知识将回落到「通用」规则"。「通用」不提供删除入口。
- **生效口径**：一条知识实际用哪套规则，由它自己的 `content_format` 字段决定——先在本板块规则里找同名内容形式，找不到回落「通用」。「知识详情 → 检索参数」的"分块方式"必须显示**实际命中的那一套**，并标注命中的是哪个内容形式（是否兜底），不能再笼统显示板块默认值。
- **改配置不追溯**：与原有规则一致，保存只影响后续入库；已有内容需重新学习成功后才应用新规则。

#### 7.2.3 ③结构化数据板块：MCP 动作清单

结构化数据不复制内容、不做切片、不进向量库，而是通过 MCP 服务参数化查询业务关系库实时取数。因此这个板块没有"切片方式"可配，取而代之的是一份**MCP 动作清单**——每个动作对应一次业务库查询，运营侧**只决定这个动作开不开**，表映射与查询语句由平台在接入时配置完成。

清单以表格呈现，每行包含：启用开关、动作名称与说明、关联的业务表/视图、主要入参、返回内容。卡片右上角显示"已启用 N/M"，关闭的行整体降透明度。代表性动作（可随业务扩展）：

| 动作 | 数据来源 | 主要入参 | 返回内容 |
|---|---|---|---|
| 商品详情 | `product` / `product_spec` | sku_id 或 keyword | 规格参数、卖点、图文详情链接 |
| 库存查询 | `inventory` | sku_id、warehouse_id（可选） | 可用库存、在途数量、预计到货日 |
| 价格与促销 | `price` / `promotion` | sku_id、quantity（可选） | 单价、阶梯价、活动名称与有效期 |
| 订单状态 | `sales_order` | order_no + 手机号后四位 | 订单状态、金额、明细行 |
| 物流跟踪 | `shipment` / `carrier_track` | order_no 或 waybill_no | 承运商、当前节点、轨迹明细 |
| 门店与网点 | `store` | city 或 lng/lat、radius | 门店名称、地址、电话、营业时间 |
| 售后工单 | `service_ticket` / `warranty` | ticket_no 或 sn_code | 工单状态、处理人、保修截止日 |
| 开票信息 | `invoice` | order_no | 开票状态、发票类型、抬头 |
| 可预约时段 | `booking_slot` | city、service_type、date_range | 可选时段、剩余名额 |

规则：关闭某动作后智能客服不再调用它，已产生的对话记录保留；**新增动作需平台侧先完成数据库接入**，再在此清单出现，运营侧不能凭空新建动作。涉及用户隐私的动作（订单状态、开票信息等）必须带身份校验入参，不允许只凭订单号裸查。

### 7.3 知识资产目录

这是模块里**唯一**的内容增删改入口，定位是"用户只需要传东西"的极简录入体验。

**Tab切换式新增交互**：打开新增知识弹窗后，根据所选板块智能显示对应的Tab导航，每个板块有不同的Tab选项组合：

- **②问答知识（faq）**：
  - Tab 1：✍️ 手动输入问答（推荐，默认）— 填写问题+答案，直接创建草稿
  - Tab 2：📤 批量上传FAQ — 上传FAQ文档
  
- **③结构化数据（structured）**：
  - Tab 1：📤 上传结构化数据（推荐，默认）— 上传 JSON/JSONL/CSV/XLSX 文件，内容形式固定为"数据"；可填写结构化字段名（逗号分隔），也可在此直接跳转"从前台页面选择"读取前台页面绑定的结构化字段

- **④内容资产（content）**：
  - 无Tab，直接引导至"从前台页面选择"（图文详情、专题、活动页等前台内容页）；同样不支持通用文件上传/填网址方式录入

- **⑤网络知识（web）**：
  - Tab 1：🔗 外部网址（推荐，默认）— 抓取保持同步
  - Tab 2：📤 上传文件 — 静态文件
  - Tab 3：🗄️ 对象存储

- **⑥行业知识（industry）**：
  - 无 Tab，也没有上传/网址/对象存储等录入方式——行业知识库由平台统一维护，企业侧只能**浏览并导入**，详见下方「从行业知识库导入」。

- **①文档知识（document）**：
  - Tab 1：📤 上传文件（推荐，默认）
  - Tab 2：🔗 外部网址
  - Tab 3：🗄️ 对象存储
  - JSON/JSONL/CSV 等结构化导出文件也走这个板块的上传 Tab，复用同一套上传+解析流程，只是解析方式改为按记录切片而非按段落切片，不新增板块或子模式概念

Tab导航位于板块选择器下方，当前Tab带蓝色下划线高亮，推荐Tab标注"推荐"蓝色徽章。切换板块时自动切到该板块的默认Tab。Tab下方直接显示对应的表单内容，无需二次点击。

**从行业知识库导入（⑥行业知识专属）**：选择⑥行业知识板块后，弹窗直接展示平台行业知识库的内容列表，运营勾选后导入到本产品组的知识资产目录。导入的资产来源方式标记为「平台」，与上传/网址/对象存储等企业自有来源区分开。

每条内容按与本产品组已有资产的比对结果给出三种状态，互斥：

| 状态 | 判定 | 可否勾选 |
|---|---|---|
| 新增 | 本产品组从未导入过这条 | 可勾选 |
| 已导入 | 已导入且导入版本 = 平台库当前版本 | 置灰、勾选框禁用 |
| 有新版本 | 已导入但平台库版本更高 | 可勾选，勾选即"更新导入"，覆盖为新版本并刷新切片数与来源引用 |

版本追溯靠资产上的 `industrySourceId`（对应平台库条目）和 `industrySourceVersion`（导入时的版本号）两个字段，状态判定基于当前页面数据而非原始 mock，保证同一会话内导入后立刻反映为"已导入"。

列表提供导入状态、一级分类、二级分类三个筛选项。**原型阶段不提供行业筛选**：行业不作为内容可见性的门槛，平台库内容全量展示，行业只作为每条内容的展示信息（显示在名称下方，形如「能源、矿产与资源 · 行业数据」）。正式版若需按 §7.2.1 配置的行业限制可见范围，在此处补上过滤即可，交互结构不变。

**从前台页面选择**：后台拿到的是前台网站结构，而不是让运营理解内部生成过程。这个选择器只服务③结构化数据和④内容资产两个板块，树里只展示这两类页面——文档知识、问答知识等其它板块各有自己的录入方式（上传文件、手动输入问答等），不混进这棵树；③结构化数据除了这条路径，也可以在"新增知识"弹窗里直接上传 JSON/JSONL/CSV/XLSX 结构化文件，两条路径二选一或都用。选择器按站点、导航层级做成真正可折叠的多级树（站点→一级导航→二级导航→…→页面），每个树节点前有三态勾选框（全选/未选/部分选中），点击可展开/收起，勾选一个节点即批量选中其下全部可选页面；叶子页面展示标题、页面类型、页面数据类型、绑定数据和结构化字段，归属从下拉改为③结构化数据/④内容资产两个 checkbox，可同时勾选（页面既有正文又有结构化字段时可以两个板块都要，每个勾选的板块各生成一条独立资产），不展示路由（对运营无实际意义）。已加入知识库的页面按 `frontendPageId` 判定为"已添加"，灰显禁用，与未加入的页面并列展示，直观演示已选/未选两种状态。勾选页面入库后，`frontendPageId`、`frontendNavPath`、`pageType`、`sourceDataMode`、`structuredFields` 写入知识资产元数据（`frontendRoute` 在这个选择器界面本身不展示，对运营无实际意义；但会写入资产，并在知识资产目录列表的「前台页面」列以文字+「↗」跳转链接形式展示，点击可新开页面跳转到该资产对应的真实前台页面，跳转地址按资产勾选的适用站点域名拼出 `frontendRoute`）；导航结构默认参与学习，用来帮助智能客服判断用户问的是哪个页面的信息。

**筛选与多选**：

- 筛选项：名称搜索、板块、来源方式、状态、行业、时效、权限（7个维度）
- 支持多选行（checkbox）：表头全选/单行勾选
- 批量状态变更：仅当所选知识状态一致时可用，显示合法的下一步动作按钮（如"批量发布""批量提交评估"），操作区域出现在表单上方，状态不一致时提示"所选知识状态不一致，无法批量操作"
- 批量修改元数据：知识入库时元数据由大模型自动匹配，量大后必然出现误判，需要人工批量纠正；仅当所选知识同属一个知识板块时可用（跨板块元数据字段体系不通用，会出现字段对不上的错配），入口置灰并提示"所选知识不在同一知识板块，不能批量修改元数据"。弹窗内 9 个元数据字段（知识库类型/行业/一二级分类/内容形式/有效状态/适用对象/语言/来源）各自带启用勾选框，只覆盖勾选的字段，未勾选字段保持每条知识原值不变，避免误清空本来正确的字段
- 知识健康体检：目录页顶部拆为「知识库概览」指标面板（承载原体检页和原命中率 KPI，按"内容库存"与"前台问答效果"分组展示知识总数、待更新、最近更新时间、待补 FAQ、知识库召回率、总检索次数、命中次数、未回答数）和「知识健康体检」问题分布条（6 类结论带数量、可点筛选，按待修复缺陷／运营信号／健康三组分列）。体检结论实时判定并作为列表的一列展示，点结论徽标进入单条修复；勾选后可批量修复，要求所选结论一致且动作对每条都适用。修复动作包括补路由、补结构化字段、同步、重新学习、标记已更新、下线，执行后即时重算结论与健康度，并写入「修复流水」。体检不创建异步任务、不做结果快照——判定规则、字段来源与闭环见 §8.5。AI 回复率、回复率损耗归因是「对话质量运营」页的对话侧指标，不在知识资产目录展示，避免同一批数字在两个页面重复呈现。

列表本身是全板块统一视图，靠"知识目录"人工文件夹分组（新建、归类）和筛选条件做二次归类，互不冲突——文件夹是运营自定义的业务分组，板块是系统固定的处理方式分类。命中率 KPI 合并进"知识健康体检"面板，"未回答问题转移"区块（原 N5 知识库页的能力）也整合在这里，形成"传内容 + 看效果 + 转化未回答问题"的一体化工作台。

**文档级信息与业务归类**：知识资产目录负责逐份填写和修改文档级元数据；元数据规范页只负责定义字段与选项，两者使用同一套字段。当前资产名称即知识标题。代表性字段取自《企业网站行业知识库分类体系说明》及配套表格的“09_知识归类模板”“10_选项配置”：知识库类型、所属行业、所属企业、一级分类、二级分类、内容形式、有效状态、来源，适用对象和语言作为可选示例。表格仍会持续更新，本期只固化字段语义和少量代表性选项，不实现 Excel 导入，也不把全部表格内容永久写死在原型中。

字段联动规则如下：

- 知识库类型固定为“行业知识库、企业公共知识库、企业业务知识库”，表示知识归属和复用范围；现有 6 个知识板块表示内容处理形态，两者必须并列展示、独立保存，修改知识库类型不得自动修改知识板块。
- 行业知识库必须选择所属行业，所属企业留空；企业公共知识库和企业业务知识库必须选择所属企业，所属行业可从企业信息继承并只读展示或经校验后修正。
- 一级分类的可选项随知识库类型变化；修改知识库类型或一级分类后，若当前二级分类不再兼容，必须清空并提示重新选择。所属企业和二级分类按企业维护，不作为平台固定全局枚举。
- 内容形式与来源方式独立，例如“上传文件”是来源方式，“政策”或“手册”是内容形式。代表性内容形式包括文章、政策、指南、FAQ、数据、案例、通知、手册、其他。
- 有效状态与生命周期状态独立：有效状态描述内容是否现行有效，代表性取值为现行有效、即将生效、已失效、待确认；生命周期状态仍按草稿、待评估、已发布、待更新、已归档流转。已失效、待确认内容默认不得作为正式回答依据；即将生效内容可入库治理，但正式检索需遵守后续生效日期策略。
- 前台页面路由和导航路径是来源上下文，不替代行业/企业/一级分类/二级分类组成的业务分类路径。

### 7.4 知识详情

点开一条知识后看到的是这条内容的完整档案：元数据、健康度四维分解（质量/时效/复用/反馈，带改善建议）、更新历史时间线、同步信息（如果是需要保持更新的来源类型）。

核心是**内容双栏预览**：左边原文，右边是解析出来的切片，参照 RAGFlow 的交互设计——右侧切片列表可以搜索筛选，勾选后批量启用/禁用/删除；点开单个切片弹出编辑框，可以改正文、改类型标注、加关键词/可能的提问方式/标签、单独启用禁用。这一层是运营人工介入"解析质量"的最后手段：自动解析不理想时，不用重新调整板块级参数重跑，可以直接在这一条上手工修正；切片的"问题"数量也直接影响该资产的质量健康度分项（见 §8.1）。

切片被编辑、禁用或删除后，资产标记为“需重新学习”；重新学习成功前，线上检索继续使用上一成功版本，不能因为编辑未完成而返回半更新内容。详情中的元数据、状态、健康度、同步信息、门禁和更新历史必须同一版本刷新。

**正文/附件与切片的关系**：正文或附件保留在知识资产的文档内容版本上，是可追溯的权威原始内容；解析切片是非结构化内容学习后生成的版本化子对象，不替代原文。每个切片必须关联资产 ID 和学习版本，并继承检索所需的文档级元数据，包括知识库类型、行业、企业、一级/二级分类、内容形式、有效状态、来源，以及现有知识板块、适用门户、权限、标签和精确溯源信息。继承字段以文档为唯一事实来源，不允许在切片上单独修改而与文档失配；切片自身仍可维护正文、类型、关键词、可能问题、标签、启用状态和问题标记。

修改会影响过滤或召回的文档级元数据后，资产同样标记为“需重新学习”。新版本完成解析、向量化和校验并整体切换成功前，线上继续使用上一成功版本，不能混用新旧切片或元数据。标题、摘要和来源保留为文档级字段，可在检索索引中作为上下文使用，但不能只存在于某个切片中。

结构化数据是例外：其正文载体为结构化字段、Schema 或实时数据源引用，不创建通用向量切片和 embedding；详情页展示字段结构、示例数据和来源上下文，继续走数据库/MCP 等结构化查询路径。

顶部操作区的状态操作不是摆设——点击"发布""下线""标记已更新"等按钮会真实改变这条知识的生命周期状态，并联动重算健康度（发布/标记已更新会把"最近更新时间"刷新为当天，从而让时效分项回到满分）。合法的下一步动作跟着当前状态走（见 §8.2），不能跳步骤。

入库前门禁检查逐项列出通过情况，不通过的给出原因和"重新学习"的修复路径。检索参数只做摘要展示并给出跳转配置入口，不重复放编辑控件。

### 7.5 元数据规范

五部分职责：一是「文档级元数据字段与选项配置」，统一定义知识文档可填写的字段、字段含义、条件必填规则、代表性选项和维护归属，具体字段值仍在每份知识资产上填写；二是全平台通用的现有元数据枚举维护（内容形式、适用对象、有效状态、语言标签、业务用途、适用场景、门户网站），改一处全局下拉一致——**行业不在此维护**，行业体系是平台维护的两级结构，企业侧的选用范围在「知识板块 → ⑥行业知识 → 行业知识配置」圈定（见 §7.2.1），本页不再展示行业字段；三是「板块元数据总览」表——把 6 个板块的关键运营指标（条数、健康度、引用次数、自定义字段数、最近更新）放进一张可排序的表，方便运营快速定位"哪个板块最常用、最该投入维护资源"，而不用逐个板块页面去看，引用次数可切时间范围（默认"全部"，避免短窗口把长期重要但近期没被问到的板块埋没）；四是「健康度评分权重」配置——四个维度的计算口径是固定的（见 §8.1），但四项各占多少权重是运营可调的治理参数，调整时下方有实时预览，看得到"这个权重下 6 个板块各自平均分变成多少"，而不是盲调；五是「统一元数据字段」——系统内置字段只读展示，因为它们和状态机、健康度、检索逻辑绑定，改名字或删掉会让整个系统对不上；自定义字段则完全开放增删改，全部板块通用，一旦加入就会在「知识资产目录」编辑弹窗自动多出对应的输入框，填的值也会出现在「知识详情」的元数据卡片里——不是写文档用的静态表，是真的能逐条知识去维护的字段。

文档级元数据的维护边界如下：知识库类型及核心字段语义为系统固定；行业体系、按知识库类型分组的一级分类、内容形式、有效状态和适用对象等稳定选项由平台维护；所属企业、企业二级分类等租户数据由企业侧维护；知识标题、具体分类选择、来源、正文/附件、语言等值由运营逐文档填写。适用对象和语言存在选项不代表必填。知识库类型不能重命名成知识板块，也不能在此新增第 7 个处理板块。

可编辑枚举的展示顺序与「统一元数据字段」保持一致：先按内置字段顺序排内容形式、适用对象、有效状态、语言标签，再排业务用途、适用场景等非 schema 附加维度，最后是权限级别/时效等级这类系统固定、只读展示的枚举。顺序一致是为了让运营在两张表之间对照时不用来回找。

枚举新增时去除首尾空格且不允许同值重复；业务用途、适用场景、内容形式、有效状态、分类等仍被资产使用时不可直接删除，需返回关联资产数并要求先迁移或清空引用。**内容形式被某个板块的切片解析规则引用时同样不可直接删除**（见 §7.2.2），需先删除对应规则，避免出现指向不存在内容形式的悬空规则。未选择门户网站表示对当前客户全部站点生效。自定义字段名只允许小写字母、数字和下划线，且全局唯一；已存在资产值的字段需先迁移或清空后才能删除。健康度配置的预览只改页面展示，保存后才按 §8.1 的规则参与后续重算。

### 7.6 同步状态

管理"内容进来之后怎么保持更新"这件事。

**默认展示近一周 + 更多按钮**：页面默认只展示近一周有同步记录的内容，减少信息过载；右上角"更多"按钮点击后查看全部历史记录，再次点击恢复为"仅显示近一周"。

**字段与知识资产目录保持一致**：统一列表展示，字段包括：内容标题、板块、来源方式、状态、健康度、频率（定时同步可调）、上次同步、下次同步、同步状态。点击表格行跳转至对应知识详情页，减少维护成本，用户体验更一致。

**筛选条件**：板块、来源方式、同步状态三个维度，与知识资产目录的筛选逻辑保持一致。

**日志查看**：参考 RAGFlow 的日志展示，黑色终端风格弹窗，显示同步过程的详细日志（开始时间、解析文档、切片处理、成功/失败状态、建议操作）。

**同类型多选批量操作**：同步内容列表支持勾选多条内容，但只能同时选择同一同步类型（实时同步 / 定时同步 / 手动），避免把实时监听、定时抓取、手动上传三种机制混在一次操作里造成误解。选中后顶部出现批量操作条：所有类型都支持"批量立即同步/批量重试"；定时同步类型额外支持批量调整频率（每小时/每日/每周等）。如果已经选择了某一类型，其他类型的 checkbox 禁用，用户需先清空选择再切换类型。

按同步机制分三组概览卡片：前台页面内容是实时同步（发布即更新）、外部网址和对象存储是定时抓取、上传文件是手动更新（重新上传触发）。状态分布 KPI（正常/同步中/失败/未启用）给运营一个总体健康快照，不用逐组去数失败项；有失败会置顶红色提示条。

### 7.7 问答测试

给运营一个"像用户一样提问"的沙盒，验证板块调优是否有效，参考 RAGFlow 检索测试（Run Retrieval Test）的形态：左侧提问，右侧展示这次提问召回到的知识文本块。新增的"测试范围"板块多选，是配合「知识板块」配置页调优流程的关键能力——怀疑是某个板块召回不准时，可以把测试范围收窄到只测那个板块，排除其它板块内容的干扰，看结果更聚焦。右侧文本块列表展示引用来源、相似度和相关性/权威性/时效性多维评分，帮助判断"答得对不对、可信不可信"，而不只是"有没有答案"；点击左侧任意一条历史回答，可在右侧切换查看该问题对应的召回结果。

默认范围为全部板块；取消最后一个已选板块时恢复为全部板块。**匹配严格度三档固定映射为相似度得分阈值：宽松 0.25、标准 0.5、严格 0.75**，只展示相似度达到当前阈值且属于测试范围的文本块。不提供"回答风格"切换——问答测试只用于验证召回是否准确，不用于验证话术表达。本页的提问和清空操作均不写入正式对话、复用、满意度或覆盖盲区统计。

### 7.8 对话质量运营

当前客户后台的对话分析页，数据来自该客户智能客服前台的一条条对话。页面回答"哪些用户问题没有命中知识、哪些对话没有回复、哪些回答被点踩、下一步该补哪类知识"。它不是平台跨客户看板，不提供客户/行业筛选（当前后台上下文只属于一个产品组，见 §3.1）；筛选维度是时间、场景（在线客服/网站搜索/内容生成）和命中知识名称。平台侧跨客户、跨行业的质量诊断统一放在 N12「平台运营看板」中承载。

**核心 KPI**：

- **对话轮次**：当前筛选范围内的智能客服对话/问题轮次数。
- **知识库召回率**（原"命中率"）：检索是否命中相关知识。
- **AI 回复率**：AI 是否最终给出回复。
- **RAG 准确率**：命中且已回复，并且没有点踩、没有转人工，作为"答得对"的代理指标。
- **回复率损耗归因**：解释召回率 → 回复率之间的损耗来自哪里（知识缺失/召回低/规则拦截/模型拒答/系统异常）。
- **满意度**（原"好评率"，拆分为满意度/点踩率）：只统计有明确赞踩反馈的记录。
- **覆盖盲区数**：当前待处理快照。

**页面内展示指标计算规则**：每个 KPI 旁边或下方展示公式，避免运营只看到数字不知道来源。详细公式见 §8.3.1。

**筛选维度**：

- 时间范围：今天/近7天/近30天/全部，决定对话轮次、召回率、回复率、准确率、满意度等事件类指标的统计口径。
- 场景：在线客服 / 网站搜索 / 内容生成。
- 命中知识名称搜索：用于定位某条知识被哪些对话引用、用户反馈如何。

**调用记录 + 未回答：默认近一周 + 更多按钮**

- **对话记录**：默认展示近一周的对话记录，右上角"更多"按钮点击后查看全部历史。表格包含日期/场景/用户问题/命中知识/相似度/反馈/是否回复/未回复原因/是否转人工/引用片段，可按场景筛选、按命中知识名称搜索，点击"原始对话"查看完整对话上下文。
  - **对话处理信息**：
    - 是否回复
    - 未回复原因：知识缺失、召回低、规则拦截、模型拒答、系统异常
    - 是否转人工
    - 引用片段信息，用于辅助判断 RAG 准确率

- **覆盖盲区（未回答问题）**：默认展示近一周的未回答问题聚类，右上角"更多"按钮查看全部。每条盲区包含：用户在问什么、本客户出现次数、影响会话数、最近提问时间、建议补到哪个板块、处理状态（待处理/已补录/已忽略）、优先级。
  - **盲区闭环信息**：
    - 保留按客户拆分的影响明细，但当前客户后台只读取当前客户自己的出现次数和影响会话数
    - 增加建议补录板块
    - 增加处理状态：待处理、已补录、已忽略
    - 增加优先级：由规则服务返回，页面仅展示，不在前端二次计算
    - 按优先级降序、最近提问时间倒序排序，优先处理高优先级未命中问题
  - **补录操作**：点击"补录"按钮，跳转至知识资产目录，预置板块为"问答知识"（faq），并带上问题内容作为参数，运营可直接填写答案完成补录。
  - **忽略操作**：点击"忽略"按钮，标记该问题不再提示补录（适用于超出业务范围或不需要回答的问题）。

顶部时间范围（今天/近7天/近30天/全部，默认近7天）决定了对话轮次/知识库召回率/AI 回复率/RAG 准确率/满意度这些 KPI 的统计口径，与对话记录表算的是同一批数据，确保数据一致性；覆盖盲区数是当前待处理快照，不随时间范围变化。形成"发现盲区 → 补充知识 → 召回率提升"的运营飞轮。

页面中的“知识健康体检”入口跳至知识资产目录后，应直接把问题分布条定位到“全部缺陷”档；“补录”应预置建议板块和问题主题，“忽略”后该主题立即不再计入待处理盲区和待补 FAQ。

### 7.9 目录内知识健康体检

知识健康体检不再是独立页面，也不是异步任务，而是「知识资产目录」里的常驻能力。体检结论所依赖的全部输入（健康度、命中次数、前台路由、结构化字段、生命周期状态）都是资产上已有的数据，任何时刻都能算出来，因此不需要"发起任务、后台执行、等待结果"这一层——**诊断是实时的，需要留存的只有修复动作**。判定规则和字段来源见 §8.5。

页面上分三块承载：

**一是「知识库概览」指标面板**，保留原健康体检页和原命中率卡片的可视化信息：内容库存组展示知识总数、待更新、最近更新时间、待补 FAQ；前台问答效果组展示知识库召回率、总检索次数、命中次数、未回答数。右上角是「修复流水」入口。

**二是「知识健康体检」问题分布条**，把 6 类结论做成带数量的可点筛选项，并按性质分三组，避免运营把"没人用"误读成"内容坏了"：

| 分组 | 包含结论 | 含义 |
|---|---|---|
| 待修复缺陷 | 需更新、缺路由、缺字段（另有「全部缺陷」聚合档） | 内容本身有确定缺陷，应当修复 |
| 运营信号 | 无命中、低复用 | 内容不一定有问题，只是没被用到；是否处理需人工判断 |
| 健康 | 有用 | 继续参与检索，无需动作 |

点任一档即按该结论筛选列表，一次点击就完成"筛出一批有问题的文档"。数量口径与列表严格一致：先按常规筛选项（名称、板块、来源方式、知识库类型、行业、分类、内容形式、有效状态、时效、权限、目录分组、状态）算出范围，体检结论作为最后一层筛选，因此**分布条上显示 12，点开后列表必然是 12 条**，不会因叠加其它筛选而对不上。

**三是列表内的「体检结论」列**，位于「知识资产（知识标题）」之后。每行实时判定并展示结论徽标，悬停显示判定原因；点徽标或操作列的「修复」按钮打开单条修复弹窗，展示页面上下文、判定时间、修复前健康度、当前健康度、问题原因、处理建议和该结论对应的修复动作。结论为"有用"的行不出现「修复」按钮。

**修复分单条和批量两种**。单条在弹窗内执行；批量在勾选后的操作区执行，且必须满足两个约束：所选知识的体检结论一致（不同性质的问题不能按同一种方式处理），且动作对每条选中知识都适用——取各条 `repairActions` 的交集，例如没有同步来源的知识不会出现"批量同步"。结论不一致时给出明确提示，引导先按结论筛选再批量修复。

**编辑元数据**支持单条与批量两种。单条编辑在弹窗内直接改全部字段。批量编辑面向一个明确的现实问题：知识入库时，知识库类型、行业、一级/二级分类、内容形式、有效状态、适用对象、语言、来源这 9 项元数据都由大模型自动匹配，量大之后必然出现分类跑偏、行业挂错等误判，一条条改效率太低。批量修改元数据要求**所选知识必须同属一个知识板块**——不同板块的元数据字段体系、分类枚举不同（如结构化数据板块和文档板块的一级分类选项并不通用），跨板块批量改字段会出现"这个字段对那条知识根本不适用"的错配，因此选择跨板块时批量修改入口置灰，并提示"所选知识不在同一知识板块，不能批量修改元数据"。板块一致时，弹窗内 9 个字段各自带一个启用勾选框，运营只勾选确实要纠正的字段（例如只勾"所属行业"），其余字段保持每条知识各自原值不变，避免不小心用批量弹窗里的空值/默认值覆盖掉本来正确的字段。

修复执行后即时重算结论与健康度，并把动作写入「修复流水」。流水记录知识资产、修复前结论、处理动作、健康度变化（带增减量）、操作人、时间，点资产名可跳转知识详情。**留存修复流水而不是体检快照**：诊断随时可重算、没有回溯价值，真正需要回答的是"谁在什么时候修了什么、修完有没有变好"。

对话侧的召回、回复、满意度、原始对话明细继续在「对话质量运营」查看；覆盖盲区仍从对话质量页跳回知识资产目录补录。从对话质量页点「知识健康体检」跳转到目录时（`?check=1`），自动定位到「全部缺陷」档。

## 八、核心指标计算口径

上一版 PRD 遗漏了这部分——健康度、状态机、调用记录这几处"数字/状态从哪来"没写清楚，导致原型里一度出现"两组手填数字凑数"、"状态改不了"、"调用记录没有日期、KPI 文案和数字对不上"这些不闭环的问题。本节把口径写清楚，方便研发、测试和产品评审统一理解。

### 8.1 健康度：四维分数怎么算，总分怎么加权

四个分项都按同一套规则从知识资产、解析切片和对话反馈中计算，输出 0–100：

| 维度 | 计算口径 |
|---|---|
| 质量 | 从 100 分开始扣分：资产名或任一切片命中敏感词时一次性扣 40 分；同板块存在疑似重复资产时一次性扣 20 分；有问题切片扣分为 `min(30, round(问题切片数 / 切片总数 × 100 × 0.3))`。三项相加后最低为 0 分。 |
| 时效 | 结构化数据因实时查询，默认满分；其他内容按距上次更新的时间与该内容的新鲜度要求比较，越久未更新分数越低。 |
| 复用 | 按统计窗口内被检索命中的次数计算，`min(100, 40 + 命中次数 × 12)`；统计窗口默认近 30 天，可在高级配置中调整。 |
| 反馈 | 统计窗口内有明确赞踩的命中记录。样本数小于最小样本量（默认 3）时给中性基准 75 分；达到样本量后，`round(点赞数 /（点赞数 + 点踩数）× 100)`。 |

新鲜度阈值按时效等级分级：实时类内容要求 1 天内更新，小时级内容要求 3 天内更新，每日级内容要求 14 天内更新，静态内容要求 180 天内更新。

**总分** = 四项按权重加权求和，默认权重质量 30 / 时效 25 / 复用 25 / 反馈 20，**可在「元数据规范」页调整**（四项滑块之和须为 100，调整后有实时预览）。草稿/待评估状态的资产尚未走完评估流程，健康度显示为"—"（不参与计算）。

板块级健康度 = 该板块所有已评估资产健康度的平均值，同一套规则自底向上算出，不是另外单独维护的数字。草稿、待评估和无健康度的资产均不进入分母。

### 8.2 生命周期状态机：谁能把状态从 A 改到 B

| 当前状态 | 允许的人工动作 | 触发方式 |
|---|---|---|
| 草稿 | 提交评估 → 待评估 | 人工（知识详情页 / 资产目录编辑弹窗按钮） |
| 待评估 | 发布 → 已发布；退回草稿 → 草稿 | 人工 |
| 已发布 | 下线 → 已归档 | 人工 |
| 待更新 | 标记已更新 → 已发布；下线 → 已归档 | 人工 |
| 已归档 | 恢复为草稿 → 草稿 | 人工 |

**唯一的自动转移**：已发布内容超过"2 倍新鲜度阈值"未更新，页面展示状态自动降级为"待更新"，因为"是否过期"是客观事实、不需要人工判断；发布、下线、归档这些需要业务判断的动作，不做自动化，必须人工点击。所有列表和详情页都以展示状态为准，保证"过期了但还没人工确认"的资产也能被看到并操作。

「知识详情」页和「知识资产目录」编辑弹窗都提供统一的状态操作组件（当前状态徽标 + 合法下一步按钮），不再是可以随意改成任意值的自由下拉——避免把"运营手滑改错状态"和"真实的业务流转"混为一谈。

### 8.3 调用记录与各类统计数字的时间维度

对话记录需要记录提问时间、场景、用户问题、命中知识、是否回复、未回复原因、是否转人工、用户反馈、原始对话内容，以及该对话是否关联某个覆盖盲区主题。这些信息是复用/反馈健康度计算、按日期/按文档筛选、以及从健康体检 Top 主题回溯原始对话的数据基础。

**对话处理信息**：
- AI 是否给出回复
- 未回复原因：知识缺失、召回低、规则拦截、模型拒答、系统异常
- 是否转人工
- 转人工原因
- 引用片段信息
- 用户反馈：点赞、点踩、无反馈

#### 8.3.1 对话质量运营指标计算规则

对话质量运营页所有事件类指标都来自当前客户智能客服前台对话。先套同一组筛选条件：时间范围（今天/近7天/近30天/全部）、场景、命中知识名称搜索。筛选后的每条记录代表一次用户提问及 AI 处理结果。

| 指标 | 分子 / 分母 | 公式 | 说明 |
|---|---|---|---|
| 对话轮次 | 筛选后的对话记录数 | 对话轮次 = 当前筛选范围内的用户提问次数 | 一次用户问题进入知识库检索/问答链路记 1 轮对话。 |
| 知识库召回率 | 命中知识的对话轮次 / 对话轮次 | 召回率 = 命中知识的对话轮次 / 对话轮次 × 100% | 衡量这轮对话是否找到相关知识。未命中会进入覆盖盲区聚类候选。 |
| AI 回复率 | 已回复对话轮次 / 对话轮次 | AI 回复率 = 已回复对话轮次 / 对话轮次 × 100% | 衡量这轮对话最终是否给出回答。即使召回成功，也可能因规则拦截、模型拒答、低置信度等原因不回复。 |
| RAG 准确率 | 命中知识且已回复、未点踩、未转人工的轮次 / 命中知识轮次 | RAG 准确率 = 准确命中次数 / 命中知识次数 × 100% | 原型阶段用"未点踩且未转人工"作为答得对的代理信号；后续可替换为人工质检/模型评测得分。 |
| 满意度 | 点赞轮次 / 有明确赞踩反馈的轮次 | 满意度 = 点赞数 /（点赞数 + 点踩数）× 100% | 无反馈记录不进分母，避免把沉默用户误算成满意或不满意。 |
| 点踩率 | 点踩轮次 / 有明确赞踩反馈的轮次 | 点踩率 = 点踩数 /（点赞数 + 点踩数）× 100% | 与满意度互补，用于快速定位差评对话。 |
| 回复率损耗 | 召回率与 AI 回复率的差值 | 回复率损耗 = 知识库召回率 - AI 回复率 | 用于解释"检索找到了，但 AI 没有答"的损耗。损耗原因按未回复原因分组统计：知识缺失、召回低、规则拦截、模型拒答、系统异常。 |
| 覆盖盲区数 | 当前客户仍待处理的问题聚类数 | 统计当前客户待处理盲区主题数量 | 快照类待办，不随顶部时间范围变化；每个盲区聚合当前客户相似未命中/未回复问题，并记录出现次数、影响会话数、建议板块和优先级。 |
| 盲区优先级 | 本客户出现次数、影响会话数、最近提问时间的综合排序 | 出现次数越多、影响会话越多、最近越常出现，优先级越高 | 目的是让运营先补"自己客户前台反复问、影响会话多"的问题。 |

**回复率损耗归因规则**：只统计 AI 没有回复的记录，根据未回复原因分组：

- 知识缺失：检索侧没有足够内容支撑回答，应进入补录任务。
- 召回低：可能有内容但相似度、阈值或切片导致没有稳定命中，应检查检索参数或切片。
- 规则拦截：通常是权限、敏感词、低置信度策略导致不回复。
- 模型拒答：通常是模型安全策略或无法组织可信答案。
- 系统异常：检索服务异常、编排失败或其他系统问题导致没有回复。

#### 8.3.2 对话质量运营「覆盖盲区」计算规则

对话质量运营里的「覆盖盲区」不是平台跨客户榜单，只看当前客户自己的待处理问题。它的业务含义是：客户前台用户反复问到某类问题，但智能客服没有答上来，系统把这些相似失败问题聚合成主题，按影响程度排序，方便运营优先补知识。

**入榜条件**：

1. 只展示当前仍待处理的主题；已经补录、已经忽略的主题不再进入 Top。
2. 只展示当前客户自己的问题，不展示平台其他客户的问题。
3. 只统计"没有回答上来"的失败对话，包括没有命中知识、低召回导致未回复、知识缺失导致未回复等情况。
4. 已经回复但用户点踩的记录不进入覆盖盲区，这类问题属于回答质量问题，应进入 RAG 准确率、满意度或低质量回答复盘。

**排序规则**：

先看该主题在当前客户前台出现了多少次，出现越多越靠前；如果出现次数相同，再看影响了多少个会话；如果仍然相同，最近被问到的主题排在前面。页面默认展示近一周，可通过「更多」查看全部。

**字段展示**：

| 列 | 说明 |
|---|---|
| 问题主题 | 相似失败问题聚合后的主题名，例如"私有化部署支持"。 |
| 本客户出现次数 | 当前客户前台用户问到该主题的次数。 |
| 影响会话数 | 被该主题影响的去重会话数，用于避免同一会话反复追问被过度放大。 |
| 最近提问 | 当前客户最近一次问到该主题的时间。 |
| 建议板块 | 系统建议补录到哪个知识板块，例如问答知识、行业知识、内容资产。 |

**闭环动作**：

- **查看对话**：打开该主题关联的原始对话样本，展示用户问题、机器人是否回复、是否命中知识、未回复原因等，帮助运营判断为什么没有答上来。
- **去补录**：跳转到知识资产目录，默认带入建议板块和问题主题，运营补充答案或资料后，该主题从待处理变为已补录。
- **忽略**：如运营判断该问题超出业务范围或不需要回答，可忽略该主题，忽略后不再进入健康体检 Top。

待补 FAQ 数量统计当前客户待处理主题中，建议补到问答知识板块的数量。该指标是快照类待办，不随对话质量运营页顶部时间范围变化。

统计数字分两类，处理方式不同：

- **快照类**（当前状态，不需要时间范围）：概览 KPI、同步状态的方式概览/状态分布、知识资产目录的召回率 KPI、对话质量运营的"覆盖盲区"数——这些是"现在的库存/待办情况"，不是"这段时间发生的事"，加时间筛选没有意义。
- **事件计数类**（需要时间范围，本轮补上）：对话质量运营的对话轮次/知识库召回率/AI 回复率/RAG 准确率/满意度/点踩率/回复率损耗——提供"今天/近7天/近30天/全部"筛选（默认近7天），KPI 卡片的时间文案跟着选择动态显示，不再写死"近7天"却按全量数据计算；对话记录表新增按命中知识名称搜索。元数据规范「板块元数据总览」的"引用次数"列同样可切时间范围，默认给"全部"（这张表是横向排序找高频板块用的，默认时间窗口太短会把长期重要但近期没被问到的板块埋没）。

### 8.4 入库前清洗与质量评估策略：每一项判定都有具体依据

板块配置页「入库前清洗与质量评估策略」卡片下，去重、打分策略、答案准确性人工审核三项都对应一套**可解释的判定规则**，不是摆设的 toggle；这套规则同时驱动「知识板块」配置页的开关状态、「知识详情」页的门禁检查结果、以及 §8.1 健康度"质量"分项——三处读的是同一组事实，不是三份互相不知道对方的数据。隐私信息脱敏是内容处理步骤而非判定项，见表后单独说明。

| 配置项 | 判定依据 |
|---|---|
| 去重 | 一期只在同板块内比较标题与标签，不做全文语义去重：标题按分词集合计算 Jaccard 相似度，并为每个相同标签增加 0.1；综合相似度大于等于阈值（默认 0.60）即判定疑似重复，并返回相似资产与分数。 |
| 打分策略（质量评分拦截阈值） | 质量打分从 100 分开始扣分：敏感词命中、疑似重复、切片解析问题都会扣分；低于阈值时，门禁检查中的"质量打分是否达标"不通过。 |
| 答案准确性人工审核（②问答知识专属） | 唯一不能自动判定的一项，由运营在知识资产目录或知识详情页手动标记；未标记人工审核时，不允许直接通过该项门禁。 |

**隐私信息脱敏**：按板块勾选的隐私类型（手机号/身份证号/邮箱地址/银行卡号/姓名/家庭地址）逐条扫描资产名称和全部解析切片正文，命中后替换为对应占位符（如手机号 `13812345678` → `{手机号}`）再写入索引，原文不落库、不进入向量检索；开启时脱敏结果直接体现在「知识详情」页的切片内容里，不产生扣分，也不作为门禁判定项——它解决的是"进库前把 PII 处理掉"，不是"内容能不能入库"。与「元数据规范」页维护的敏感词库（合规检查用，见下表"合规与敏感信息过滤"门禁项）是两套独立机制，互不影响。

门禁检查在原先 6 项基础上新增第 7 项"质量打分是否达标"，让打分阈值真正在门禁里起作用；「知识详情」页的"入库前门禁检查"卡片每一行下方都展示这行依据文本（比如"命中：绝对、保证"或"与某条资产相似度较高"），不通过时额外给出处理建议。门禁结果必须从真实内容信号得出，不能靠固定样例硬编码。

### 8.5 知识健康体检：结论怎么判出来、每个字段从哪来、修复怎么闭环

体检的设计前提是：**判定所需的输入全部已经存在于资产、切片和对话记录上，不需要额外采集，也不需要异步任务**。所以体检是一个纯函数——同样的资产在同一天永远得到同样的结论；修复改变了输入，结论随之改变。这一节把这条链路从输入到闭环写完整。

#### 8.5.1 判定的四个输入

| 输入 | 取值来源 | 谁写进来的 |
|---|---|---|
| 健康度 `health` | 四维加权总分，见 §8.1 | 入库评估、发布、同步、重新学习、状态流转时重算；草稿/待评估为 0（界面显示"—"） |
| 命中次数 | 对话记录中 `assetId` 等于本资产的条数 | 前台问答实时写入对话记录（§8.3）；问答测试不写入 |
| 生命周期状态 | `effectiveStatus(asset)`，即 `status` 叠加"超期自动降级"，见 §8.2 | 人工流转写 `status`；"已发布超过 2 倍新鲜度阈值未更新 → 待更新"由系统自动判定，不落库 |
| 前台页面字段 | `connect`、`frontendRoute`、`frontendNavPath`、`sourceDataMode`、`structuredFields` | 从前台页面入库时带入；也可在目录编辑弹窗或体检修复动作中补齐 |

#### 8.5.2 结论判定规则：单一主结论，按优先级短路

每条知识只给一个主结论，按下表**从上到下**依次匹配，命中即返回，不再往下判。优先级的依据是"先修能不能用，再看有没有用"——结构缺陷让知识根本无法正确支撑问答，必须排在使用情况之前。

| 优先级 | 结论 | 判定条件 | 判定原因文案 | 分组 |
|---|---|---|---|---|
| 1 | 缺路由 | `connect === '前台页面'` 且 `frontendRoute` 为空 | 缺少前台页面路由，无法判断用户问题属于哪个页面 | 缺陷 |
| 2 | 缺字段 | 板块为③结构化数据，或 `sourceDataMode` 含"结构化字段"，且 `structuredFields` 为空 | 页面数据需要按字段保存，但当前没有结构化字段 | 缺陷 |
| 3 | 需更新 | `effectiveStatus === 'stale'`，或 `health < 60` | 健康度偏低，或已超过时效要求 | 缺陷 |
| 4 | 无命中 | 命中次数 = 0 | 近期对话没有命中该知识 | 信号 |
| 5 | 低复用 | 命中次数 ≤ 1，或 `health < 75` | 近期命中次数少，复用不足 | 信号 |
| 6 | 有用 | 以上都不满足 | 近期命中 N 次，健康度 M | 健康 |

因此：同时缺路由和缺字段时显示"缺路由"；已过期且零命中时显示"需更新"而不是"无命中"——先把内容修新，再讨论有没有人用。

**分组的产品含义**：缺陷是内容本身的确定问题，运营应当修；信号只说明这条知识没被用到，可能是冷门但必要的内容（如合规条款），是否处理需人工判断。两者在问题分布条上视觉分离，「全部缺陷」聚合档只包含优先级 1–3。

#### 8.5.3 页面上下文字段怎么拼

修复弹窗和列表悬停提示里的"页面上下文"按以下顺序取第一个可用值，目的是让运营一眼看出这条知识对应前台哪个位置：

1. 有 `frontendRoute` → `{frontendNavPath}` · `{frontendRoute}`
2. 来源是前台页面但无路由 → 固定文案"前台页面缺少路由"
3. 其它 → `sourceRef`（来源引用），为空时退到 `connect`（来源方式）

#### 8.5.4 每个结论对应哪些修复动作

修复动作不是固定一套按钮，而是按结论给出可执行项；同一动作在不同结论下的语义一致。

| 结论 | 可用修复动作（按推荐顺序） |
|---|---|
| 缺路由 | 补齐路由、编辑元数据、重新学习 |
| 缺字段 | 补齐字段、编辑元数据、重新学习 |
| 需更新 | 立即同步（仅有同步来源时）、重新学习、标记已更新 |
| 无命中 | 编辑元数据、重新学习、下线知识 |
| 低复用 | 编辑元数据、重新学习、立即同步（有同步来源）或标记已更新 |
| 有用 | 重新学习（不出现「修复」入口，仅弹窗内可用） |

各动作的实际改动：

| 动作 | 对资产的改动 | 调用接口 |
|---|---|---|
| 补齐路由 | 写入 `frontendRoute`、`frontendNavPath`、`sourceDataMode`（缺省值待运营确认），健康度不低于 72 | `PUT /api/kb/assets/{id}` |
| 补齐字段 | 写入 `structuredFields` 默认字段集，`sourceDataMode` 置为"页面正文+结构化字段"，健康度不低于 78 | `PUT /api/kb/assets/{id}` |
| 立即同步 | 重新抓取来源，`syncStatus` 置成功、刷新 `lastSync`，健康度不低于 82 | `POST /api/kb/assets/{id}/sync` |
| 重新学习 | 重跑解析/切片/向量/索引，健康度提升 12 分且不低于 80 | `POST /api/kb/assets/{id}/relearn` |
| 标记已更新 | 状态置已发布并启用检索，刷新 `updatedAt`，健康度不低于 85 | `PUT /api/kb/assets/{id}` |
| 下线知识 | 状态置已归档、停止参与检索，保留历史 | `PATCH /api/kb/assets/{id}/status` |
| 编辑元数据 | 打开目录的编辑弹窗，由运营手工补标签、业务归类、页面信息、权限 | `PUT /api/kb/assets/{id}` |

所有动作都会把 `updatedAt` 刷成当天（下线除外），这也是"修完时效分回满"的原因。上表中的健康度保底值是修复动作的**即时反馈估值**，用于让运营立刻看到效果；下一个评估周期仍按 §8.1 的真实公式重算，两者不冲突。

#### 8.5.5 批量修复的约束

批量修复必须同时满足：

1. 所选知识的体检结论完全一致——不同性质的问题不能按同一种方式处理；
2. 动作对每条选中知识都适用，即取各条可用动作的**交集**（例如选中的知识里有一条没有同步来源，"批量同步"就不出现）；
3. 「编辑元数据」需逐条填写，不进入批量；
4. 执行前二次确认，展示将影响的条数。

结论不一致时不隐藏入口，而是提示"所选知识的体检结论不一致，请先按上方结论筛选后再批量修复"，把正确路径指出来。

#### 8.5.6 闭环：修复如何回流成新的输入

```
资产字段 / 切片 / 对话记录
        │（§8.1 健康度、§8.2 状态机、§8.3 命中数）
        ▼
体检结论（§8.5.2 实时判定，纯函数，不落库）
        │
        ▼
问题分布条计数 ── 点击 ──► 列表筛选 ──► 单条或批量修复（§8.5.4）
                                              │
                    ┌─────────────────────────┘
                    ▼
        改写资产字段 / 触发同步或重新学习
                    │
                    ├─► 健康度、状态、更新时间重算 ─┐
                    │                              │
                    └─► 写入「修复流水」（留存）     │
                                                   │
        ◄──────────── 结论与计数即时刷新 ◄──────────┘
```

闭环的三个一致性要求：

- **同一事实只有一处来源**：体检结论不落库、不缓存，任何页面（目录、详情、概览、板块总览）看到的健康度、状态、命中次数必须来自同一次计算，不允许出现"体检说需更新、列表显示已发布"这类互相矛盾的展示。
- **修复即时可见**：动作执行后在一次刷新内，结论徽标、健康度、分布条计数、列表筛选结果同步更新；单条弹窗保留进入时的健康度作为"修复前"对照，让本次修复的增量可见。
- **只留存动作，不留存诊断**：修复流水记录知识资产、修复前结论、动作、健康度前后值、操作人、时间，用于回看和汇报；体检结论本身随时可重算，不做快照。

#### 8.5.7 数据接口

| 用途 | 接口 |
|---|---|
| 拉取修复流水 | `GET /api/kb/repair-logs`（支持按 `assetId` 过滤、`limit` 限制条数） |
| 记录一次修复 | `POST /api/kb/repair-logs`，入参 `assetId`、`action`、`fromStatus` |

体检结论没有独立接口——它由前端／服务端基于已拉取的资产数据按 §8.5.2 计算，避免多一次往返和一份可能过期的副本。

### 8.6 切片规则命中口径与行业配置口径

这两处都是"一条数据到底按哪套规则走"的判定，容易在实现时各写一套，故在此固定口径。

#### 8.6.1 切片规则怎么命中

```
一条知识入库 / 重新学习
        │
        ▼
读取该知识的 content_format（内容形式，文档级元数据）
        │
        ├─ 在所属板块的规则里找 contentFormat 相同的专属规则 ─► 命中，用这套参数
        │
        └─ 找不到 ─────────────────────────────────────► 回落「通用」规则
```

配套约束：

- 「通用」规则**每个板块恒存在且唯一**，不可删除，是回落终点；因此命中判定不存在"找不到任何规则"的分支。
- 判定只看 `content_format` 一个字段，不叠加板块以外的条件；同一板块内一个内容形式最多一条规则，不存在优先级冲突。
- 新增专属规则时以「通用」当前参数为初始值，属于**创建时快照**，此后两者独立；之后改「通用」不会同步到已创建的专属规则。
- ③结构化数据板块不参与本判定（无切片，走 §7.2.3 的 MCP 动作）。
- 规则变更只对后续入库生效；已有内容重新学习成功后才切换到新规则，与既有的"配置不追溯"原则一致。
- 「知识详情 → 检索参数 → 分块方式」展示的必须是本条知识**实际命中**的规则及其内容形式来源，不得展示板块默认值。

#### 8.6.2 行业配置的取值与约束

| 项 | 口径 |
|---|---|
| 行业体系层级 | 两级：一级行业 → 二级行业，平台维护，企业侧只读。个别一级行业（如「其他」）可以没有二级。 |
| 一次选择的完整性 | 选到一级即算完整**当且仅当**该一级下没有二级；否则必须选到二级。 |
| 数量上限 | 主行业 1 个（必填）+ 额外行业最多 2 个，合计 3 个。 |
| 去重 | 主行业与各额外行业两两不能相同（一级、二级都相同视为重复）。 |
| 默认值来源 | 产品组创建时从 `customer_id` 已登记行业带入（见 §3.1），运营可改；客户层后续变更不回写。 |
| 冷却期 | 365 天，从上次保存成功之日起算。**首次配置不受限**（未配置过时按钮始终可点）。冷却期内按钮置灰并显示下次可更改日期。 |
| 变更后果 | 不再属于新选行业的行业知识库内容停止从平台同步新版本，**历史已导入内容保留**。变更前必须二次确认并展示这句后果。 |
| 下游取值 | 供筛选/下拉使用的字符串口径取"选择中最细的一层"：有二级取二级，无二级取一级。 |

原型阶段的例外：知识资产目录顶部的行业筛选项来自**列表数据中实际出现过的行业值**，不取企业行业配置；「从行业知识库导入」也不按行业过滤（见 §7.3）。原因是原型阶段行业不作为内容可见性门槛，若绑定企业配置，未配置时下拉为空、已配置时又会因演示数据行业口径不一致而筛出 0 条。正式版按 §8.6.2 的下游取值口径接回即可。

## 九、核心业务对象

| 业务对象 | 说明 |
|---|---|
| 客户 / 产品组 / 站点 | 平台的三层归属结构（见 §3.1）。客户 `customer_id` 是行业信息的源头；产品组 `product_group_id` 是**知识库的归属边界**，一组一套知识库；站点 `site_id` 是客户面向不同地区购买的网站产品，多个站点共享所在产品组的同一套知识库。 |
| 知识板块 | 系统内置的 6 类知识分类，决定内容的处理方式、清洗策略、检索策略和运营统计口径；运营不可新增或删除板块，只能配置各板块的处理策略。 |
| 切片解析规则 | 板块下按「内容形式」挂的一套切片参数。每个板块必有且仅有一条不可删除的「通用」兜底规则，另可按内容形式添加 0..N 条专属规则；一条知识按自身 `content_format` 命中规则，命中不到回落「通用」（见 §7.2.2、§8.6.1）。③结构化数据板块不适用。 |
| MCP 动作 | ③结构化数据板块的实时取数能力，一个动作对应一次业务库参数化查询，含名称、说明、关联业务表、入参、返回内容和启用开关。运营侧只决定启停，表映射与查询语句由平台接入时配置（见 §7.2.3）。 |
| 企业行业配置 | 产品组级的行业圈定结果：一个主行业 + 最多 2 个额外行业，每个都是"一级行业 + 二级行业"的完整选择。决定本产品组可从平台行业知识库取用哪些行业的内容；一年内最多更改一次（见 §7.2.1、§8.6.2）。 |
| 平台行业知识库条目 | 平台统一维护、跨客户共享的行业内容，含行业、名称、分类路径、内容形式、版本号、切片数等。企业侧只能浏览并导入到自己的产品组；导入后的资产用 `industrySourceId` + `industrySourceVersion` 追溯来源与版本（见 §7.3）。 |
| 知识资产（知识文档） | 知识资产目录里的核心对象，一条记录代表一份知识内容；以当前资产名称作为知识标题，包含知识板块、知识库类型、行业/企业、一级/二级分类、内容形式、有效状态、来源、正文或附件，以及现有适用门户网站、业务用途、场景、时效、权限、生命周期状态、健康度、标签、备注、同步信息等。来源为前台页面时还必须关联页面 ID、路由、导航路径、页面类型、数据类型与结构化字段，列表标题下方展示该导航路径（树形路径），并可通过「↗」按适用站点域名拼出完整地址新开页面跳转到该前台页面。①文档知识额外记录文件大小 `fileSize`；⑤网络知识额外记录抓取来源地址 `siteUrl`，均展示在列表标题下方，`siteUrl` 可点击新开页面跳转到来源站点。 |
| 知识库类型与业务分类路径 | 知识库类型表示业务归属和复用范围，固定为行业知识库、企业公共知识库、企业业务知识库；业务分类路径由行业、企业、一级分类、二级分类组成。它与决定处理方式的 6 个知识板块独立，不因板块变化而自动变化。 |
| 文档内容版本 | 保存某一版正文、附件或结构化数据源引用及其解析/学习状态。非结构化内容每次成功重新学习后整体启用新版本；失败或未完成时继续使用上一成功版本。 |
| 解析切片 | 非结构化知识文档某一成功学习版本的子对象，是知识详情页"内容"区域的最小管理单元；继承检索所需的文档级元数据，并保存切片正文、位置/父子关系、类型、关键词、问题、标签、问题标记、向量化和启用状态。运营可查看、搜索、编辑、启用/禁用切片，切片问题会影响资产质量分。结构化数据不创建此对象。 |
| 门户网站 | 同一客户后台下的多语言或地区站点，知识可选择适用哪些站点；未选择时默认全部站点可用。 |
| 更新历史 | 记录知识创建、编辑、重新学习、同步、状态变更等操作，供运营回溯。 |
| 对话记录 | 智能客服前台的用户提问与 AI 处理结果，是对话质量运营、健康度反馈分、引用次数、未命中主题回溯的基础。 |
| 覆盖盲区 | 从未命中或未回复对话中聚类出的待补主题，包含出现次数、影响会话数、最近提问、建议补录板块和处理状态。 |
| 健康度分解 | 质量、时效、复用、反馈四个维度的分数及权重，用于解释知识健康度总分。 |
| 门禁检查结果 | 入库前清洗与质量评估的结果，包括是否通过、判定依据和不通过时的处理建议。 |
| 敏感词库 | 元数据规范页维护的合规检查词库，供「知识详情」页"合规与敏感信息过滤"门禁项及质量打分公式使用，与板块配置页的"隐私信息脱敏"是两套独立机制。 |

知识资产同时具有两个独立状态维度：“有效状态”表示内容在业务上是否现行有效，“生命周期状态”表示资产处于草稿、评估、发布、更新或归档流程的哪个阶段。两者必须分别保存和展示，不得用“已发布”等同于“现行有效”，也不得用“已失效”替代下线/归档操作。

## 十、当前范围说明

- 当前原型用于确认页面结构、交互流程、指标口径和运营闭环；真实数据接入、权限、登录、审批流转等能力不在本轮原型范围内。
- 未覆盖：权限与登录、审批流转、真实的向量检索/RAG 后端。多租户的归属结构已在 §3.1 明确（客户 → 产品组 → 站点，知识库挂在产品组层），但本轮原型不实现租户隔离的鉴权与数据隔离本身，页面按单一产品组上下文演示。
- 页面文案已刻意去除"分块算法/向量库/RAG"等技术黑话，仅在配置页面向愿意深入的运营人员提供参数级控制。
- 本次文档级元数据需求只定义后续原型中的字段、页面位置、联动和数据关系，不包含后端持久化、数据库迁移、真实向量库、生产级版本发布、企业主数据管理或 Excel 导入。
- 《企业网站行业知识库分类体系说明》及配套 Excel 是字段设计参考，不是运行时依赖；由于表格仍会更新，原型只选取少量代表性字段和选项，除知识库类型等稳定语义外不承诺与表格逐列同步。
- 不新增、删除或重命名现有 6 个知识板块，不把知识库类型改造成处理板块；不改变现有健康度公式、板块条数/健康度/引用次数等统计口径。
- 健康体检的**指标定义未变**（仍是有用/低复用/需更新/无命中/缺路由/缺字段 6 类结论），变的是承载方式：由"建异步任务、看体检记录"改为"实时判定、按结论筛选、单条或批量修复、留存修复流水"（见 §7.9、§8.5）。
- 切片解析方式由"一板块一套参数"改为"板块下按内容形式挂多套规则"，但**规则内的参数项及其取值范围未变**，「通用」规则等价于改动前的板块级配置（见 §7.2.2、§8.6.1）。
- 本期不实现生效日期、失效日期等完整时间政策，仅先保留独立的有效状态字段；更细的日期判断规则在后续数据模型和接口设计中补充。

## 十二、验收标准与明确不在范围

### 12.1 验收标准

1. 前台页面资产可从完整网站导航中选择，且每条资产均可追溯到站点、页面、路由、导航路径与页面数据形态。
2. 目录内体检的结论按 §8.5.2 实时判定并按缺陷／信号／健康三组呈现，点结论即可筛出对应知识；单条与批量修复动作可闭环，修复流水可回看，不存在独立的“知识健康体检”导航、路由或异步任务。
3. 同一资产在目录、详情、体检结论、概览和元数据规范中的状态、健康度、命中次数必须一致；本节测试用例全部通过。
4. 所有指标有明确分子、分母、统计窗口、空值表现和边界值；后端服务端计算通过固定测试数据校验，前端不得产生第二套口径。
5. 修复操作完成后，目录、详情、同步状态、体检结论徽标和问题分布条计数在一次刷新内一致；修复流水完整记录动作与健康度前后值。
6. 概览、知识板块、板块配置、资产目录/详情、元数据规范、同步状态、问答测试、对话质量运营均按第六、七节描述实现；跨页面跳转携带必要筛选或上下文，不丢失业务动作。
7. 资产目录和知识详情同时展示知识板块与知识库类型，字段名称和含义与元数据规范一致，用户能够明确理解前者决定处理方式、后者表示业务归属与复用范围。
8. 文档级元数据的字段、条件必填、选项来源和联动规则可按 `TC-KB-050`～`TC-KB-060` 验证；正文/附件、学习版本、切片继承和结构化数据例外的关系无歧义。
9. 元数据规范新增“文档级元数据字段与选项配置”后，仍完整保留 6 个板块总览、健康度配置、敏感词、门户范围和现有自定义字段能力，且不改变健康度、体检和引用统计口径。
10. PRD 和原型中的 Excel 衍生字段只作为代表性样例，不宣称穷举全部字段或与后续表格版本自动同步。
11. 知识库的数据边界为 `product_group_id`：同一产品组下多个站点共享一套知识库，跨产品组数据不可见；行业默认值可从 `customer_id` 带入且允许运营修改（见 §3.1）。
12. 每个板块的切片配置支持按内容形式挂多套规则，「通用」恒存在且不可删；一条知识按自身 `content_format` 命中规则、命中不到回落「通用」，知识详情展示实际命中的规则，可按 `TC-KB-061`～`TC-KB-065` 验证。
13. ⑥行业知识板块的行业配置为"主行业 1 个 + 额外行业最多 2 个"，两级联动选择、去重校验、365 天冷却期与变更二次确认齐备，可按 `TC-KB-066`～`TC-KB-071` 验证；行业不再出现在元数据规范页的可维护枚举中。
14. ③结构化数据板块不展示切片/清洗/检索表单，改为 MCP 动作勾选清单，每个动作可独立启停并展示数据来源、入参与返回内容，可按 `TC-KB-075` 验证。

### 12.2 本期不在范围

- 不建设或暴露页面设计器、CMS 栏目编辑、页面布局编辑能力；本模块只消费“前台网站结构/前台页面”结果。
- 不实现全文语义查重、跨板块去重、版权自动裁决或 AI 自动改写知识；一期去重仅使用标题与标签相似度。
- 不建设登录、角色权限、审批、多租户隔离、真实向量检索引擎、模型编排和生产级调度重试策略；接口需预留操作者与站点/客户上下文。
- 不实现分类体系 Excel 的自动导入、同步和版本差异处理，不在本期建设完整企业主数据、二级分类管理后台或生效/失效日期引擎；原型仅呈现文档级元数据的代表性字段、选项和交互。
- 不把问答测试记录计入真实运营指标、资产复用或覆盖盲区。
- 不自动发布、自动下线或自动删除知识；所有会改变业务可用性的状态迁移均由用户明确触发。
