# 知识库项目对齐智能客服 Pro 数据看板差距分析

> 对照材料：  
> 1. 《知识库配置产品需求文档（PRD）》  
> 2. 《智能客服Pro月度总结与双看板埋点方案》  
>
> 结论先行：当前知识库 PRD 偏“知识库配置后台”，重点是内容上传、板块配置、切片、同步、健康度、问答测试。它已经能支撑知识管理，但还没有完全支撑智能客服 Pro 后续要做的两套数据看板：  
> - 产品后台：监控产品力、AI 质量、客户使用效果，指导产品迭代和销售成交。  
> - 客户后台：让单个客户看到自己买了智能客服 Pro 后效果如何、知识库哪里要补、下月怎么优化。

---

## 一、产品后台需要补齐的内容

产品后台的目标不是让客户日常操作，而是给产品、运营、商务、客户成功看全局：产品力好不好，哪些客户用得好，哪些客户知识库差，AI 回复为什么掉，哪些行业适合销售。

### 1. PRD 里已有、可以复用的内容

| 已有能力 | PRD 位置/表现 | 可复用价值 |
|---|---|---|
| 知识资产目录 | 知识资产列表、板块、来源、状态、健康度、创建/更新时间 | 可作为知识库资产明细基础 |
| 知识板块配置 | 切片解析、清洗策略、检索策略 | 可支撑不同知识类型的处理方式管理 |
| 健康度 | 质量、时效、复用、反馈四维 | 可作为知识资产质量的基础评分 |
| 问答测试 | 测试范围、回答、引用来源、相似度 | 可作为人工验证知识库效果的工具 |
| 质量与运营 | 调用次数、命中率、好评率、覆盖盲区、调用记录 | 可作为知识库效果监控的雏形 |
| 覆盖盲区 | 未命中问题聚类、出现次数、建议板块、补录 | 可作为“待补知识”的基础能力 |
| 同步状态 | 同步方式、失败告警、立即同步、日志 | 可支撑知识新鲜度和同步失败排查 |

### 2. 需要替换或调整的内容

| 当前 PRD 表述/字段 | 建议替换为 | 原因 |
|---|---|---|
| 命中率 | 知识库召回率 | 和智能客服 Pro 现有看板口径统一，表达“是否找到相关知识” |
| 好评率 | 用户反馈率 + 满意度/点踩率 | 好评率太粗，产品后台需要看正负反馈和低质回答 |
| 覆盖盲区 | 未命中主题/未回复原因 | “盲区”偏知识缺口，无法解释 AI 召回了但没回复的问题 |
| 调用次数 | 按客户、行业、场景拆分的知识调用次数 | 产品后台必须能定位“哪个客户/行业/场景”有问题 |
| 健康度四维中的“复用” | 复用 + 服务效果 | 仅被引用次数不够，需要加入回复率、准确率、转人工等服务效果 |
| 问答测试 | 问答测试 + 回答质量标记 | 测试不只是看引用，还要标记答得准不准、是否可用 |
| 调用记录 | AI 回答质量明细 | 需要补充是否回复、未回复原因、是否兜底、是否转人工、用户反馈 |
| 板块元数据总览 | 客户/行业/板块三层汇总 | 只看板块不够，产品后台要看客户和行业差异 |

### 3. 产品后台需要新做的内容

| 新做内容 | 优先级 | 解决什么问题 | 需要的关键字段 |
|---|---|---|---|
| 客户维度打通 | P0 | 现在 PRD 主要是知识资产维度，无法回答“哪个客户知识库好/差” | 客户标识、行业、套餐、销售/渠道、开通时间 |
| 客户知识库健康分 | P0 | 产品后台需要识别高风险客户、沉睡客户、待运营客户 | 客户标识、文档数、更新时间、召回率、AI 回复率、未命中主题数、转人工率 |
| AI 回复质量明细 | P0 | 解释召回率约 99%、AI 回复率约 88% 之间的损耗 | 会话 ID、问题、命中文档、相似度、是否回复、未回复原因、是否兜底、是否转人工、反馈 |
| RAG 准确率 | P0 | 解决“找到了知识但答得对不对”的核心产品力问题 | 命中文档、引用片段、答案、用户反馈、人工/规则判定结果 |
| 未回复原因分类 | P0 | 定位问题是知识缺失、召回低、规则拦截、模型拒答还是系统异常 | 未回复原因、场景、客户、行业、时间 |
| 转人工归因 | P0 | 判断 AI 没解决哪些问题，指导知识库补充和模型优化 | 是否转人工、转人工原因、转人工前问题、命中文档 |
| 知识库待补主题榜 | P0 | 把低质回答、未回复、转人工沉淀成可执行知识补全任务 | 主题、出现次数、影响客户数、建议板块、优先级 |
| 客户/行业质量排行榜 | P1 | 支撑客户成功跟进和商务销售案例 | 客户标识、行业、召回率、回复率、准确率、满意度、线索贡献 |
| 知识库效果与线索转化关联 | P1 | 证明知识库质量是否影响互动和线索 | 客户标识、知识命中、会话、线索、页面、转化结果 |
| 产品力质量看板 | P1 | 给产品/商务统一看产品质量证据 | 召回率、AI 回复率、RAG 准确率、CSAT、转人工率、未回复原因 |
| 低质量回答复盘池 | P1 | 让产品/算法/知识运营定期复盘坏例 | 问题、答案、命中文档、反馈、原因、处理状态 |

### 4. 产品后台本次 PRD 建议纳入的最小范围

如果本次开发不想发散，建议只新增以下 P0 能力：

| 本次建议新做 | 是否必须 | 原因 |
|---|---|---|
| 客户标识贯穿知识资产、调用记录、盲区记录 | 必须 | 没有客户维度，后续产品后台和客户后台都无法落地 |
| 质量与运营页增加客户/行业筛选 | 必须 | 让产品方能看哪个客户、哪个行业质量差 |
| 调用记录增加“是否回复/未回复原因/是否转人工” | 必须 | 对齐智能客服 Pro 的 AI 回复率和转人工监控 |
| 命中率改名为知识库召回率 | 必须 | 对齐现有看板口径 |
| 覆盖盲区增加“影响客户数/建议补充 FAQ/处理状态” | 必须 | 从问题列表变成运营任务 |
| 知识详情/调用记录增加引用片段 | 建议 | 支撑 RAG 准确率和客户信任 |
| 增加 RAG 准确率指标 | 建议 | 如果本期来不及自动计算，至少预留人工标记和反馈字段 |

## 二、客户后台需要补齐的内容

客户后台的目标不是让客户看全局产品力，而是让客户知道：我买了智能客服 Pro 后，接待了多少访客、产生了多少线索、AI 答得怎么样、知识库缺什么、下一步要做什么。

### 1. PRD 里已有、可以复用的内容

| 已有能力 | 可复用到客户后台的方式 |
|---|---|
| 知识资产目录 | 客户查看自己的知识资料、状态、更新时间 |
| 知识详情 | 客户查看原文、切片、引用来源、健康度 |
| 覆盖盲区 | 客户看到哪些问题没答上，需要补哪些 FAQ |
| 问答测试 | 客户模拟访客提问，验证知识库是否能回答 |
| 同步状态 | 客户知道网站栏目、外部链接、文件是否同步失败 |
| 健康度 | 客户看到知识库是否过期、质量是否低 |
| 引用来源 | 客户理解 AI 答案来自哪份资料 |

### 2. 需要替换或调整的内容

| 当前 PRD 表述/页面 | 客户后台建议替换为 | 原因 |
|---|---|---|
| 质量与运营 | 知识库效果/知识库体检 | “质量与运营”偏内部术语，客户更关心效果和待办 |
| 调用次数 | 本月 AI 回答次数/知识命中次数 | 客户不理解“调用”，要翻译成业务语言 |
| 命中率 | 知识覆盖率/知识库召回率 | 客户需要知道“知识够不够”，不是技术命中 |
| 好评率 | 用户满意度/有用率 | 客户更关心访客是否觉得答案有用 |
| 覆盖盲区 | 待补知识/未回答问题 | 直接告诉客户要补什么 |
| 板块健康度 | 知识库健康体检 | 用客户能理解的方式展示：过期、缺失、低满意、待更新 |
| 问答测试 | 模拟访客提问 | 用业务语言降低理解门槛 |
| 元数据规范 | 不建议直接给客户展示 | 客户不需要维护全局 schema，最多维护标签和站点 |

### 3. 客户后台需要新做的内容

| 新做内容 | 优先级 | 解决什么问题 | 需要的关键字段 |
|---|---|---|---|
| 客户知识库首页总览 | P0 | 客户一眼看到本月知识库带来的效果 | 接待访客数、互动用户数、AI 回复数、线索数、转人工数、知识库健康分 |
| 本客户知识库健康体检 | P0 | 客户知道自己的知识库是否能支撑 AI 回答 | 文档数、更新时间、召回率、AI 回复率、未命中主题、过期文档 |
| 未回答问题/待补 FAQ | P0 | 把“答不上”转成客户能执行的补知识任务 | 问题、出现次数、最近出现时间、建议答案、建议板块、处理状态 |
| 热门问题分析 | P1 | 客户知道访客最关心什么 | 问题关键词、出现次数、关联页面、是否产生线索 |
| 低满意回答列表 | P1 | 客户知道哪些答案访客不满意 | 问题、答案、引用知识、点踩/满意度、建议处理 |
| 转人工原因分析 | P0 | 客户知道哪些问题 AI 解决不了 | 转人工问题、原因、次数、关联知识缺口 |
| 线索关联会话 | P0 | 客户能从线索回看对话，提升销售跟进质量 | 线索信息、来源页面、会话摘要、访客问题、AI 回答 |
| 页面知识效果 | P1 | 客户知道哪些页面知识不足或转化差 | 页面 URL、接待量、互动率、线索率、未回答问题 |
| 客户月报 | P1 | 客户能内部汇报产品价值，增强续费感知 | 本月接待、互动、线索、AI 回复、知识缺口、优化建议 |
| 运营建议/待办 | P1 | 不只展示数据，还告诉客户下一步做什么 | 待补知识、待更新文档、低满意回答、推荐话术 |

### 4. 客户后台本次 PRD 建议纳入的最小范围

| 本次建议新做 | 是否必须 | 原因 |
|---|---|---|
| 客户维度数据隔离 | 必须 | 客户后台只能看自己的知识库、会话、线索，不能看全局或其他客户 |
| 知识库体检页 | 必须 | 客户需要知道自己的知识库哪里有问题 |
| 待补 FAQ/未回答问题列表 | 必须 | 这是客户最容易行动的知识库运营入口 |
| AI 回复率、知识库召回率按本客户展示 | 必须 | 对齐智能客服 Pro 客户效果看板 |
| 转人工原因/未回复原因 | 建议 | 帮客户理解为什么 AI 没解决 |
| 线索关联会话 | 建议 | 如果本期范围允许，应优先做，因为能直接体现商业价值 |
| 客户月报 | 建议 | 可先做基础版，后续再自动生成 PDF/分享链接 |

## 三、本次知识库 PRD 最需要补的一句话

当前 PRD 已经能说明“知识怎么录入、怎么配置、怎么同步、怎么看健康度”，但还需要补上两条主线：

1. **产品后台主线**：按客户/行业监控知识库质量和 AI 回复质量，定位产品力问题，支撑销售和客户成功。
2. **客户后台主线**：让单个客户看到自己的知识库效果、未回答问题、线索关联和待办建议，证明购买智能客服 Pro 后确实带来了价值。

如果只做当前 PRD，知识库会像一个“内容管理工具”；补齐上面两条主线后，它才会成为智能客服 Pro 的“产品力监控 + 客户运营闭环”的核心模块。
