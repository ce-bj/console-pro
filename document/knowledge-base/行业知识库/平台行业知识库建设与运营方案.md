# 平台行业知识库建设与运营方案

更新日期：2026-09-17

本指南用于建设平台共享的行业知识库，供同一行业的门户网站引用。先以制造业中的一个具体二级行业完成建设，再按相同步骤扩展其他行业。

## 执行顺序

```text
1. 确定建设哪个行业
   ↓
2. 确定要做的知识分类和数量
   ↓
3. 按分类收集原始资料
   ↓
4. 整理为文档或FAQ
   ↓
5. 检查内容和数量，完成验收
   ↓
6. 录入对应分类，测试后发布
   ↓
7. 定期检查、更新，再扩展下一批
```

| 步骤 | 本步要交付什么 | 完成后进入下一步的条件 |
|---|---|---|
| 确定行业 | 一份建设范围记录 | 行业、门户、地区、服务主题明确 |
| 确定分类 | 一张分类任务表 | 每类要做什么、数量和完成日期明确 |
| 收集资料 | 原始资料及来源清单 | 来源、版本、适用范围及使用权限可核实 |
| 整理知识 | 按分类组织的文档和FAQ | 内容完整，依据可定位，格式统一 |
| 内容验收 | 验收结果及问题清单 | 本期任务完成，错误已修正 |
| 入库发布 | 可检索、可使用的知识 | 分类、解析、问答及门户隔离测试通过 |
| 更新扩展 | 更新记录及下一批任务 | 已上线内容按期维护，新任务范围明确 |

**以下数量是制造业首批建设参考。其他行业使用同一分类和流程，启动时确认本期数量。原始资料、整理成果和系统检索切片分别计数。**

## 第一步：确定建设哪个行业

### 1. 从分类表选择行业

使用《企业级知识库分类体系 - new.xlsx》：

- “02_行业分类”：选择一级行业和二级行业。当前有50个一级行业，具体建设落实到二级行业。
- “03_行业知识库”：选择知识内容的分类。当前有24个一级知识分类、189个二级分类条目。

制造业首批可从“通用设备行业”或“金属制品行业”中，选择一个已有门户需求的二级行业。入库时填写表内准确名称。

### 2. 填写建设范围

| 需要确认的内容 | 填写要求 |
|---|---|
| 一级行业、二级行业 | 从02表选择 |
| 服务门户 | 首批选择2个相关门户，用于收集需求和验证成果 |
| 服务对象 | 例如采购咨询者、技术咨询者、产业信息查询者 |
| 本期主题 | 例如产品基础、加工方法、质量检测、政策标准 |
| 地区和语言 | 例如全国共性知识、中文；地方事项单独注明地区 |
| 目标问题 | 收集约100条原始问法，去重后确定50个优先问题 |
| 页面需求 | 确认需要支持的产品详情页和解决方案页 |
| 完成日期 | 分别确定资料收集、内容整理、验收和发布的日期 |

行业共性知识进入行业知识库。门户自己的产品参数、生产能力、报价、联系方式、交期和订单信息，由对应门户维护。

**本步完成标准：**能明确说出“给哪些门户、解决哪些共性问题、首期覆盖到哪里”。

## 第二步：确定分类、交付内容和数量

### 1. 先区分两种入库格式

| 格式 | 是什么 | 什么时候使用 |
|---|---|---|
| 文档类 | 围绕一个主题的完整说明，也可以是目录、数据表、规范或记录 | 概览、技术说明、政策、标准、指南、案例、术语、数据等 |
| FAQ | 一个标准问题、对应答案、相似问法和依据 | 可以独立回答的明确问题 |

“技术与工艺”“行业术语”等是**知识分类**；“文档类”“FAQ”是**内容格式**。

例如：加工方法的完整说明放在“技术与工艺—加工方法”，采用文档类；由它提炼的“这种方法适用于什么场景？”放在“常见问题—条件”，采用FAQ，并关联原文档。

### 2. 按24类建立任务

按下表为每类填写“本期建设、后续建设或不适用”。本期建设的类别填写实际数量和完成日期。二级知识分类使用03表中的名称。

下表给出制造业首批的具体任务。数量按整理后的成果计算；“1篇/条/套”均对应一个独立维护的业务主题。

| 知识分类 | 收集什么资料 | 需要整理成什么 | 首批数量 | 这一类如何验收 |
|---|---|---|---:|---|
| 行业概览 | 官方统计、行业年度报告、研究报告 | 文档：定义、范围、现状、趋势、区域格局 | 5篇 | 5个主题齐全；事实注明时间与来源 |
| 产业链与供应链 | 产业研究、原料与供应资料、渠道分析 | 文档：产业链全景、上下游、关键供应与风险说明 | 8篇 | 上下游关系清楚；风险与结论有依据 |
| 行业主体 | 主管部门、协会、研究及服务机构官网 | 文档/名录：名称、职责、官网和可查询内容 | 10条 | 每条信息可在原机构核实 |
| 行业业务 | 行业指南、公开业务资料、经核实的访谈 | 文档：核心业务、场景、模式和业务规则 | 8篇 | 写清参与方、输入、输出和适用条件 |
| 产品与服务 | 标准、产品技术资料、服务说明 | 文档：通用产品或服务类型、用途和参数含义 | 15篇 | 产品类型与企业具体产品区分；用途和条件清楚 |
| 政策法规 | 正式文件、附件、修订信息和官方解读 | 文档：政策原文及适用范围记录 | 15项 | 标题、文号、版本、效力信息和适用范围完整 |
| 标准规范 | 官方标准目录及获准使用的正文 | 文档/目录：标准名称、编号、范围、状态和正文链接 | 20项 | 状态及替代关系可核；目录与全文获取状态分开 |
| 办事与业务流程 | 正式办理、申报、核验及查询指南 | 文档：条件、材料、步骤、渠道和结果 | 5篇 | 地区、办理主体、渠道、时限等信息有依据 |
| 行业数据 | 官方公报、运行数据、原始研究数据 | 文档/数据表：指标定义、口径及数值 | 15个指标 | 数值、单位、时期、地区、口径和来源齐全 |
| 行业术语 | 标准、专业教材、原始技术资料 | 文档/术语表：定义、别名、易混点、中英文对照 | 50条 | 一个概念一条；定义可核，同义词合并 |
| 典型案例 | 官方案例、原始项目说明和公开结果 | 文档：背景、问题、做法、结果、适用条件 | 5篇 | 有过程和结果；案例事实可追溯 |
| 常见问题 | 优先问题清单及已审核知识 | FAQ：问题、相似问法、答案和依据 | 50题 | 一题一个意图；答案准确、完整且有据 |
| 页面规范 | 相关行业公开产品页和解决方案页 | 文档：产品详情页规范、解决方案页规范 | 2套 | 包含模块、字段、必填项、填写示例和检查清单 |
| 风险与合规 | 正式规则、监管通报和公开风险提示 | 文档：风险场景、依据、注意事项和处理渠道 | 10篇 | 适用条件明确；提示内容经专业核验 |
| 行业动态 | 新政策、新标准、新报告、技术及市场发布 | 文档/记录：事件、发布时间、变化及影响 | 10条 | 原链接、日期和影响明确；过时内容可识别 |
| 技术与工艺 | 技术规范、专业文献和原始技术说明 | 文档：原理、工艺、选型、加工和检测方法 | 15篇 | 对象、方法、适用条件、参数依据完整 |
| 资质与认证体系 | 官方目录、认证规则、发证和核验说明 | 文档：认证类型、性质、范围和核验渠道 | 8篇 | 适用产品、地区、发证主体与条件明确 |
| 市场与需求 | 市场研究、公开采购需求和需求访谈 | 文档：细分市场、用户需求、采购行为和供需分析 | 8篇 | 样本、范围、时间和结论依据明确 |
| 市场与竞争格局 | 企业公开资料、行业研究和公开份额数据 | 文档/名录：企业记录6条、格局分析4篇 | 10条 | 企业信息有出处，比较维度一致 |
| 招投标与采购市场 | 公开采购渠道、规则、招标及中标公告 | 文档：规则/渠道说明5篇，公告记录10条 | 15条 | 公告日期、截止时间或结果状态可核 |
| 商务与交易惯例 | 示范文本、协会资料和可核实交易样本 | 文档：计价、交付、验收、质保、结算和合同惯例 | 6篇 | 区分通行做法、可协商条件和正式要求 |
| 人才与职业资格 | 官方职业标准、资格目录和培训说明 | 文档：岗位能力、资格及学习路径 | 5篇 | 岗位要求与资格要求区分，查询渠道明确 |
| 国际贸易与跨境 | 一个目标市场的官方规则和公开服务说明 | 文档：报关、认证、交付和跨境事项 | 5篇 | 目标市场、产品条件、版本和依据明确 |
| 内容与表达规范 | 已核验规则、术语、页面样本和内容要求 | 文档：用语、表达、证据要求和写作检查规范 | 6份 | 有推荐写法、证据要求、示例和检查项 |

**全部按表实施时：共306条成果，其中FAQ 50条、文档类256条。文档类中含20条时效记录，其余236条为相对稳定的内容。**

国际贸易、招采等类别按门户需求启用。暂不建设的类别写明原因，并从本期数量中扣除。其他行业采用同一任务结构，按实际主题和需求调整数量。

### 3. 计数与归类规则

- 一份原始报告可以支持多篇知识文档，原报告只登记一次。
- 一个标准的目录记录与关联正文作为同一项标准成果。
- 一个指标的多期数值放在同一指标记录或关联数据表中。
- 一个术语的别名、一个FAQ的相似问法并入同一条。
- 同一成果只设一个主分类，其他分类通过关联引用。
- 综合报告和原始文件保留完整上下文；自行整理的主题文档按独立主题拆分。
- 平台解析产生的检索切片不计为新增知识成果。

**本步完成标准：**24类都有建设状态，本期每项任务都有明确交付、数量、完成日期和验收要求。

## 第三步：收集原始资料

### 1. 按顺序查找

1. 先找主管部门、官方统计、标准平台和正式公共服务渠道。
2. 再找行业协会、研究机构、专业出版物和原始技术资料。
3. 企业官网用于核实该企业的公开信息，以及观察产品和页面字段。
4. 转载与搜索摘要作为线索，追溯到原始发布方后再使用。

制造业可从国家统计局、工信部、国家标准平台及相关协会开始。具体入口包括：[国家统计局行业分类](https://www.stats.gov.cn/sj/tjbz/gmjjhyfl/)、[工信部行业数据](https://www.miit.gov.cn/gxsj/)、[全国标准信息公共服务平台](https://std.samr.gov.cn/gb.html)、[国家标准全文公开系统](https://openstd.samr.gov.cn/)。

### 2. 制造业首批资料量参考

| 资料类型 | 建议数量 | 选择要求 |
|---|---:|---|
| 报告、白皮书 | 5份 | 总体观察1、数字化1、质量或绿色发展1、选定细分行业2 |
| 统计资料 | 6份 | 最近3个已发布年度公报，加3份相关近期运行资料 |
| 政策文件 | 15份 | 对应第二步政策任务的实际主题 |
| 标准记录及可用正文 | 20项 | 对应产品、工艺、质量和安全等主题 |
| 办理与查询指南 | 5份 | 对应5个拟整理流程 |
| 案例资料 | 5份 | 每份有背景、实施过程和公开结果 |
| 机构资料 | 10份 | 机构官方介绍或职责页面 |
| 技术与交易资料 | 8份 | 技术资料5、公开交易示范文本或指引3 |
| 认证资料 | 5份 | 对应认证目录、规则和核验说明 |
| 市场与采购资料 | 5份 | 需求、采购行为、规则或渠道资料 |
| 企业公开资料 | 10份 | 与所选细分行业相关的公开信息 |
| 岗位与资格资料 | 3份 | 官方职业标准、资格目录或培训说明 |
| 跨境资料 | 3份 | 与选定产品及一个目标市场相匹配 |
| 页面样本 | 8页 | 至少3个相关主体，产品页4、解决方案页4 |
| **静态资料合计** | **108份/项** | **按原始文件或独立页面去重** |
| 行业动态与招采公告 | 20条 | 分别10条，单独维护日期和状态 |

资料数量用于安排工作。已有一份资料足以支持多个任务时直接复用；证据不足时补充采集。资料完成量与知识完成量分开统计。

### 3. 每份资料登记什么

登记：**资料名称、发布机构、原始链接或文件位置、发布日期/版本、适用行业与范围、对应任务、获取状态、可使用范围、检查日期。**

获取状态使用：待获取、仅介绍/目录、已取得正文、待授权、不可获取。

### 4. 资料接收标准

| 检查项 | 接收要求 |
|---|---|
| 相关性 | 能支持本期某项任务、问题或页面需求 |
| 来源 | 发布方明确，能定位原文 |
| 版本 | 正式版、草案、历史版和修订版可区分 |
| 适用范围 | 行业、地区、产品、对象及时间范围明确 |
| 内容完整 | 可取得的内容足以支持拟提取的结论 |
| 权限 | 原件保存、内容加工、检索使用和对外展示范围已确认 |

只取得目录或介绍时，登记书目信息和可核实的内容。权限或版本未确认的资料保留待核状态。

**本步完成标准：**本期任务有可用资料或明确的缺口记录。缺口注明缺什么、影响什么任务、下一步是补采、申请获取还是调整范围。

## 第四步：整理为文档或FAQ

### 1. 文档类怎么写

自行整理的文档优先使用MD或DOCX；数据和名录可用XLSX/CSV；原始政策、标准、报告保留授权范围内的原始文件。实际支持的上传格式先在平台验证。

一篇主题文档使用以下结构，按实际内容保留适用章节：

```markdown
# 文档标题

## 适用范围
行业、对象、地区、产品或场景。

## 核心内容
定义、事实、规则或方法，按主题分节。

## 步骤或字段说明
流程步骤、材料、参数解释或页面字段。

## 条件与注意事项
适用前提、例外及需要补充确认的信息。

## 来源与依据
发布机构、文件名称、版本、链接、页码或章节。
```

不同内容按以下要求补齐：

| 内容 | 必须写清的部分 |
|---|---|
| 术语 | 定义、别名、易混点、来源 |
| 机构或企业记录 | 名称、类型、职能/公开业务、官网、核实日期 |
| 数据表 | 指标、数值、单位、时期、地区、口径、来源 |
| 流程 | 条件、材料、步骤、渠道、时限、费用、结果；未知项明确待核 |
| 技术说明 | 原理、方法、适用对象、条件、证据 |
| 案例 | 背景、问题、措施、已披露结果、适用限制 |
| 认证 | 类型、性质、适用范围、发证与核验渠道 |
| 页面或表达规范 | 模块/规则、填写要求、示例、检查清单 |
| 动态或公告 | 事件、发布时间、截止/有效时间、当前状态、原链接 |

原始文件保持原文结构，另登记分类、范围与版本。扫描件提供核对后的OCR文本；图表补充文字说明；数据表使用明确表头，一行一条记录，单位和时间单独列出。

页面与表达规范标注为“平台编制”，写明依据与版本。法规要求、资料事实和编辑建议分别表述。

### 2. FAQ怎么写

一条FAQ包含：

| 字段 | 要求 |
|---|---|
| 标准问题 | 一个完整问题，一个明确意图 |
| 相似问法 | 可选，建议2—5种；同一答案适用的问法放在一起 |
| 答案 | 直接回答问题，写清适用条件、必要步骤和例外 |
| 依据 | 关联原始资料或已审核文档，注明证据位置 |
| 适用范围 | 对象、地区、产品及必要时间条件 |

长流程、完整技术说明和规范正文放文档类，FAQ概括关键答案并关联文档。FAQ批量交付用XLSX/CSV，一行一条问答，相似问法放同一单元格。

示例：

```text
知识分类：常见问题—材料
标准问题：编写产品详情页前，需要准备哪些资料？
相似问法：产品介绍需要提供什么？产品页需要准备哪些内容？
答案：按本行业产品详情页规范，准备产品名称及类别、用途、
参数与单位、适用条件、相关证明材料，以及交付售后和询价信息。
具体必填项以适用的页面规范为准；缺少的事实先补充核实。
依据：关联已审核的《产品详情页内容规范》及对应字段章节。
适用范围：采用该页面规范的行业与门户。
```

该示例用于说明问答格式，正式入库时关联实际已审核文档。

### 3. 每条知识都要填写的入库信息

| 信息 | 填写方式 |
|---|---|
| 知识库类型 | 行业知识库 |
| 一级行业、二级行业 | 从02表选择 |
| 一级知识分类、二级知识分类 | 从03表选择 |
| 内容格式 | 文档类或FAQ |
| 标题 | 文档填写主题名称；FAQ填写标准问题 |
| 适用范围 | 行业、对象、地区、产品、语言及时间条件 |
| 来源 | 原始资料及页码、章节或表号 |
| 版本与状态 | 版本、相关日期、待审核/已审核/待核/已归档 |
| 下次检查日期 | 按第七步频率设置 |
| 关联内容 | 引用的文档、FAQ或历史版本 |

文件命名建议：**二级行业_知识分类_主题_版本或日期**。文件名方便管理，实际入库归属以登记字段为准。

**本步完成标准：**每项任务都有可阅读的成果，分类、格式、依据和适用范围齐全，可提交验收。

## 第五步：验收内容与数量

### 1. 逐项检查

| 验收项目 | 通过标准 |
|---|---|
| 任务完成 | 本期分类与数量达到确认后的计划；延期、取消、不适用项有记录 |
| 分类正确 | 使用Excel中的行业与知识分类；每条成果有一个主归属 |
| 格式正确 | FAQ问题与答案对应；文档有标题、正文和清晰结构 |
| 内容完整 | 满足第二步该分类的交付要求 |
| 来源可靠 | 核心事实均能定位原文；引用支持所写结论 |
| 时间与范围正确 | 现行、历史、预测和观点明确区分；地区、对象、产品及数据口径准确 |
| 数字与技术准确 | 数字、单位、参数、标准版本逐项核对 |
| 权限符合 | 内容的保存、加工和展示符合已确认范围 |
| 可维护 | 有版本、关联依据和下次检查日期 |

全部成果完成基本检查。政策、标准解释、技术参数、数据、认证、风险和FAQ完成专业内容审核。任何错误修正后重新检查；待核内容不计入正式可用数量。

### 2. 核对数量

按以下四项分别汇总：

1. 原始资料：计划数、已获取数、仅目录/介绍数、待获取数。
2. 文档类成果：计划数、已完成数、已审核数。
3. FAQ：计划题数、已完成题数、已审核题数。
4. 动态记录：当前有效数、已过期数、待核数。

一份术语表可包含50条术语成果，不能同时再把这个文件算成第51条。多期数据、附件和相似问法按第二步计数规则处理。

### 3. 检查能否解决需求

验收包括内容检查和平台问答测试。内容检查通过后，将文档或FAQ上传到平台对应的行业库，按第六步完成录入，并在平台的“问答测试”中提出相关问题，检查能否检索到对应知识。平台测试通过后再正式发布。

- 50个优先问题中，至少90%有完整、已审核的回答依据；其余明确缺口及处理方式。
- 2套页面规范分别在2个目标门户各验证一次，共4个页面样本。
- 页面样本的必填字段可填写，证据要求可理解，缺失信息有明确补充项。

**本步完成标准：**审核通过的内容进入待入库清单；未通过的内容退回修改，并标明原因。

## 第六步：录入分类并测试发布

### 1. 先试录，再批量录入

1. 确认平台支持的文档格式和FAQ导入字段。
2. 每种启用的格式先录入2—3个样例。
3. 选择行业知识库、一级/二级行业、一级/二级知识分类。
4. 上传文档或导入FAQ，填写范围、来源、版本等信息。
5. 检查样例解析效果，通过后批量导入。
6. 将导入失败、解析错误和字段缺失项退回修正。

### 2. 检查入库结果

| 检查对象 | 检查内容 |
|---|---|
| 文档 | 标题、章节、正文、表格、单位、脚注和来源完整 |
| FAQ | 标准问题、相似问法、答案和依据对应正确 |
| 分类 | 行业、知识分类和适用范围与登记一致 |
| 版本 | 当前问题引用正确版本，历史资料具有明确标记 |
| 数量 | 实际导入成果与待入库清单一致；失败项单独列出 |
| 门户引用 | 同业门户能引用共享知识，各门户专属信息保持隔离 |

### 3. 发布前测试

在平台行业库中进行问答测试，按以下步骤执行：

1. 确认待验收的文档或FAQ已上传到正确的行业和分类，并完成解析与索引。
2. 在“问答测试”中选定本次验收的行业库，提出与上传内容相关的问题，同时尝试不同问法。
3. 查看检索结果，检查是否命中预期文档或FAQ，以及命中的段落能否支持该问题的答案。
4. 检查生成的回答是否准确、完整，引用的来源、版本和适用条件是否正确。检索命中和回答正确分别记录。
5. 记录测试问题、预期命中的知识、实际检索结果、回答结果及待修改项。未命中时检查分类、解析、索引和内容表述；回答错误时检查证据与答案内容。修正后用同一问题及相似问法复测。

验收以平台实际检索和问答结果为依据，不能仅凭文件上传成功判断通过。

准备50道独立测试题：

- 一般行业或专题问题20道。
- 地区、时间、版本限定问题10道。
- 门户自身问题5道。
- 行业与门户组合问题5道。
- 超出知识范围的问题5道。
- 冲突或过期版本问题5道。

测试题使用实际问法，不直接复制全部FAQ原句。答案准确、有依据、条件匹配且范围处理正确的比例应达到90%以上；跨门户信息泄漏、错误安全参数、失效规则作现行等关键错误必须修复后再发布。

同时演练一次“修改原文档—检查关联FAQ—重新发布—两门户验证”，确认更新能够生效。

**本步完成标准：**导入核对、问答测试、页面规范验证和更新演练通过后发布，并登记当前覆盖范围和已知缺口。

## 第七步：更新内容，扩展下一批

### 1. 按资料类型检查

| 内容 | 检查频率 | 发现变化后做什么 |
|---|---|---|
| 关键政策、风险通知 | 每工作日检查重要来源 | 当日判断影响，先处理失效或错误答案，再修订 |
| 招采公告 | 使用期间每工作日 | 更新截止时间、变更公告、中标结果及状态 |
| 标准、认证、办理指南 | 标准公告及指南每周；标准/认证状态每月 | 核对替代关系、范围和生效时间，目标3个工作日内完成影响确认 |
| 数据与统计 | 每月及发布时 | 追加新时期或修订值，目标5个工作日内完成加工 |
| 白皮书与研究报告 | 每月查新版，季度复核适用性 | 获得可用新版后，目标10个工作日内完成差异提取与审核 |
| 术语、技术、产品、业务、市场、交易内容 | 每季度，关联资料变化时追加检查 | 修订内容和引用；低使用或重复内容合并 |
| FAQ | 每周检查失败问题与追问 | 补证据、修答案；高频错误目标2个工作日内处理 |
| 页面与表达规范 | 每季度及规则变化时 | 更新字段、示例和检查清单，重新验证受影响页面 |
| 主体名录、岗位资格、概览、案例 | 主体每月检查；其余半年复核 | 更新变化信息、日期和适用范围 |
| 行业动态 | 每周筛选 | 登记变化，并分派受影响知识的更新任务 |

检查频率与内容更新频率分开：未发现变化只登记检查结果；发布方有新版或内容适用性变化时才修订正文。检查失败进入待核队列。

### 2. 每次更新执行同一流程

```text
发现变化
→ 查出受影响的文档、FAQ及门户
→ 修改并审核
→ 发布新版本
→ 复测受影响问题或页面
→ 更新检查日期与变更记录
```

历史版本保留历史用途。尚未生效的规则按生效时间处理。维护期限到达时仍无法核实的重要内容，暂停作为当前答案依据。

### 3. 扩展到其他行业

制造业首期通过验收并运行两个维护周期后，按同样七步启动下一个二级行业：

1. 从02表选行业，确认门户需求与建设范围。
2. 复制第二步的24类任务结构，替换为该行业具体主题。
3. 对每类确定本期状态、数量、交付格式、日期与验收要求。
4. 查找该行业的主管机构、报告、政策、标准及专业资料。
5. 试加工10份资料，确认实际工作量后批量执行。
6. 完成内容验收、入库测试和发布。
7. 将新行业纳入更新日历，再安排下一批。

按一级行业汇总各二级行业的“待启动、建设中、待验收、已上线”状态。每月检查进度与维护积压，每季度确定下一批行业及已有行业的新增专题。各批次使用同一分类结构和质量标准，资料与数量根据实际需求确定。

文件夹是采集位置，空文件夹表示尚无资料。预留记录是计划，不表示已取得资料或完成知识。

### 2. 主Excel的填写顺序

| 工作表 | 什么时候填写 | 具体填什么 |
|---|---|---|
| 01_任务总表 | 开始前确认；后续查看进度 | B4选择建设行业；查看24类任务、目标数量、验收标准和目录；调整本期安排及完成日期 |
| 02_原始资料登记 | 找到候选资料时登记，取得正文后更新 | 原始资料名称、发布方、原文链接、日期/版本、适用范围、获取及授权状态、原始文件相对路径 |
| 03_入库文档清单 | 确定一条文档类入库成果时 | 具体知识分类、入库文档标题、文档形态、适用范围、关联原始资料名称及引用章节、入库文件相对路径、审核/入库/测试状态 |
| 04_FAQ采集 | 每整理一道FAQ时 | 标准问题、相似问法、参考答案、适用范围、依据及证据位置、审核/入库/测试状态 |
| 05_问答验收 | 上传平台行业库后 | 测试问题、预期知识、实际命中内容、回答、问题原因、截图位置与复测结果 |
| 06_分类选项 | 查看分类与下拉取值时 | 行业和知识分类来自原分类Excel；各列分别提供不同字段的选项 |

知识分类采用“一级分类｜二级分类”组合下拉，确保组合对应。预置明细使用综合分类作为占位，正式录入时改为具体二级分类。FAQ只提供“常见问题”下的二级选项。所有表格中的记录继承任务总表所选择的同一行业。

入库文档清单和FAQ采集末尾的“一级分类（自动统计）”由公式生成，用于任务总表汇总，不需手工填写。

原始资料登记回答“资料从哪里来、是否取得正文、是否可以使用”；入库文档清单回答“最终上传什么、归到哪里、是否审核和测试通过”。前者是来源，后者是成果，数量不要求相等。

```text
原始资料登记（来源）
├── 整理加工 → 入库文档清单 → 上传文档
├── 原文可直接使用 → 入库文档清单（引用同一文件）→ 上传原文
└── 提炼独立问答 → FAQ采集 → 录入FAQ
                            ↓
                      问答验收并更新状态
```

### 3. 文件如何与Excel对应

1. 找到一份报告，先在原始资料登记中填一行；取得正文后放入该主题的“01_原始资料”，更新获取状态、权限和文件路径。只有目录或介绍页时，不填成“已取得正文”。
2. 根据报告整理知识，复制“00_模板/文档模板.md”，填写内容后存入“02_整理文档”。
3. 在入库文档清单中填标题、分类、关联原始资料名称、引用章节和入库文件相对路径。符合内容及授权要求的原文可以直接登记入库，无需加工或复制文件。
4. 可以独立回答的问题填写到FAQ采集表，并关联依据文档或原始资料。
5. 上传平台，完成问答测试；截图或测试导出文件放“25_平台验收记录”，在验收表登记相对路径。
6. 根据实际审核、入库和测试结果，更新文档或FAQ对应状态。

路径均相对于主Excel所在的“行业知识库”目录，例如：

```text
01_行业资料/首期_待确定行业/16_技术与工艺/02_整理文档/加工方法说明_v1.md
```

“建议存放目录”是文件夹提示；“原始文件相对路径”和“入库文件相对路径”必须写到具体文件名。原文直接入库时，入库文件可以位于“01_原始资料”，无需照建议目录再复制一份。

表间关联按名称填写，不需要编号：“关联原始资料名称”复制原始资料登记中的名称；FAQ的“依据文档/原始资料”复制对应文档标题或原始资料名称。名称包含版本或年份以便区分，同名不同版不能混用。引用多份资料时，在同一单元格内换行列出，并在引用章节中逐一对应。名称与路径目前需手工保持一致，不会自动联动；重命名时同步更新引用。

一份资料只登记一次。多篇成果可以引用同一来源，不要因为分类不同重复保存原始文件。单个文件包含多条可独立使用的术语或指标时，可多行登记同一文件路径，但须写明各自标题及工作表、行或章节；同一内容的重复引用不算新增成果。

### 4. 填写示例

以下用制造业资料说明填写方法。资料名称、章节和文件名均为演示，不代表已收集到真实资料；正式填写时以实际来源为准。路径示例中的“首期_待确定行业”应替换为本期确定的行业目录。

#### 示例一：一份报告整理成三篇文档

假设取得《某制造细分行业年度报告_2026》，可以按三个主题整理，不需要把报告登记三次。

在“02_原始资料登记”填写一行：

| 字段 | 填写示例或要求 |
|---|---|
| 对应知识分类 | 从下拉中选择最主要的所属分类，如“行业概览｜行业概览” |
| 原始资料名称 | 某制造细分行业年度报告_2026 |
| 原始发布机构、原文URL、发布日期/版本 | 按报告实际信息填写，不以转载网站代替原始发布机构 |
| 获取状态 | 实际下载到完整正文后选择“已取得正文” |
| 使用权限、权限说明 | 根据实际授权选择；可公开浏览不等于允许平台收录和向用户提供 |
| 原始文件相对路径 | `01_行业资料/首期_待确定行业/01_行业概览/01_原始资料/某制造细分行业年度报告_2026.pdf` |

在“03_入库文档清单”填写三行：

#### 示例二：原始文件直接入库

假设一份制造业相关政策文件正文完整、文字可提取、来源和适用范围明确，并已确认允许收录，可以直接上传：

1. 在原始资料登记中填写《某制造业政策文件_现行版本》的来源、日期、权限和原始文件路径。
2. 在入库文档清单新增一行，填写该文件标题，选择政策法规下的具体分类及合适的文档形态；关联原始资料名称填写上述完整名称，引用章节填写“全文”或实际使用的章节。
3. “入库文件相对路径”直接复制“原始文件相对路径”，例如 `01_行业资料/首期_待确定行业/06_政策法规/01_原始资料/某制造业政策文件_现行版本.pdf`。
4. 内容审核通过后上传平台，检索和回答均通过测试后，再更新入库和测试状态。

结果是两张表各一行，但本地只有一个文件，只计1条文档成果。未经核实的版本或待授权资料不能因为填了清单就直接入库。

#### 示例三：从文档提炼FAQ，再做平台测试

假设已审核的《制造企业产品详情页内容规范_v1》包含“参数字段”章节，可以提炼一条独立问答：

| FAQ字段 | 填写示例 |
|---|---|
| 知识分类路径 | 常见问题｜流程 |
| 标准问题 | 制造企业产品详情页的技术参数应该怎么填写？ |
| 相似问法 | 产品参数要写哪些信息？／参数是否需要标单位？ |
| 参考答案 | 每项参数应填写名称、数值或范围、单位和适用型号；受测试条件影响的参数应同时写明条件。具体值须来自已确认的产品资料，不填写无法核实的数据。 |
| 适用范围 | 制造企业产品详情页的参数展示 |
| 依据文档/原始资料 | 制造企业产品详情页内容规范_v1 |
| 页码/章节 | 参数字段 |

上述答案仅展示编写方式，实际FAQ必须与已审核依据一致。FAQ直接写在表内，不需要再建立一个同内容MD文件，也不必在入库文档清单重复登记这道题。

将FAQ录入平台相应行业库后，在“05_问答验收”填写：

| 字段 | 操作示例 |
|---|---|
| 测试问题 | 产品参数要写哪些信息？ |
| 预期知识/行为 | 能检索到上述FAQ或对应规范，回答包含参数名称、数值、单位、型号及必要的测试条件 |
| 实际命中文档或FAQ | 记录平台实际命中的标题，未命中就如实记录 |
| 检索结果、实际回答摘录、回答结果 | 根据真实测试结果填写，不能预填“通过” |
| 平台截图/测试记录路径 | 记录 `01_行业资料/首期_待确定行业/25_平台验收记录/` 下的具体文件路径 |
| 问题原因与修正、复测结果 | 未命中或回答缺项时，检查分类、上传解析、正文和问法，修改后复测 |

检索到内容不等于回答正确；两者都达到验收要求后，才将对应FAQ的“平台测试”改为“通过”。测试表记录证据，文档和FAQ表记录当前状态，两处需要同步维护。

### 6. 开始收集与扩展行业

首次使用先选择行业，再将“首期_待确定行业”目录更名为“一级行业_二级行业”。更名后，在任务总表、原始资料登记、入库文档清单中批量替换原目录名称；下拉选择行业不会自动更改本地文件夹。

一个资料包对应一个二级行业。启动下一个行业时，复制空白资料包、选择新行业、调整任务和数量。已使用的资料包保留自己的记录，避免在有数据的工作簿中直接切换行业。整体转交时，将主Excel和“01_行业资料”一起转交，保留相对目录关系。
